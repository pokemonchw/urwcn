# URWCN 原生 UI 边界字体规范

日期：2026-10-19。适用于 Windows x86、UnReal World 3.89、Steam Build `25939378` 中已经授权且有静态证据的界面。本文件规定字体质量与接入边界，不代表相关迁移已实现、编译或发布。当前实现的待整改状态见 [实现纠正记录](evidence/20261019-implementation-correction.md)。

## 原生 UI 所有权

遵循 [项目约束](../AGENTS.md)：在已反编译确认的原生组件读取文本、构建文本或格式化文本的边界捕获完整语义，根据组件身份翻译，并把结果交还原生 UI。在已确认的原生文字输出边界拦截字形绘制，由 Mod 按本规范立即绘字。保留游戏业务、内部英文数据、选项值、输入动作和配置保存语义。

游戏继续管理文本测量的调用、居中、换行、行距、光标推进、按钮尺寸、选择框、鼠标命中、背景、表面或纹理缓存、重绘以及淡入淡出的生命周期。Mod 向已确认的原生度量接口提供真实字体度量，原生 UI 消费结果；Mod 不为这些行为维护第二套布局或缓存决策。

每次绘字使用本次原生调用提供的文本、坐标、颜色、描边、裁剪及当前目标。调用结束后不保留这次 UI 绘制指令以供日后重新绘制。原生缓存已包含文字时，后续复制、覆盖与销毁由原生资源流程处理；需要重绘时，必须由原生构建和绘制生命周期再次发起文本调用。

以下做法禁止作为字体接入方案：

- 全局跟踪 SDL 像素操作、挂接逐像素写点以维护 Mod 内容镜像，或读取整幅 surface 后通过像素 diff 推断文字的存续。
- 保存文字和 UI 位置、颜色、裁剪、覆盖次序等绘制记录，再遍历、重物化或重放这些记录；记录改名为贡献、Paint、节点或操作序列不改变其性质。
- 在最终 SDL_RenderCopy 中重建完整页面源、替换成按记录重画的高清画面，或在 SDL_RenderPresent 前收集字段、排版及叠加文字。
- 固定坐标或行槽表、整页字段快照、独立 DisplayPlan，以及把 Mod 布局反写给原生控件、选择框和鼠标命中。
- 以未出现 Present 叠字、没有页面字段表或能够编译为由，将另一套内容记录与重放机制认定为符合原生所有权。

字体度量、字形覆盖图或完整串光栅本身可以缓存；这些缓存不包含 UI 位置、控件列表、页面快照或原生内容的覆盖历史，也不决定原生 UI 内容何时存在、重绘或消失。

## 完整文本与原生度量

不能仅把 UTF-8 交给仍按字节计宽、换行和索引字形的 ASCII 路径。中文编码和宽度扩展必须接入已确认的原生接口，处理一次原生调用所代表的完整文本语义，包括空格、标点、词边界和原格式化参数。

原生内部如需传输编码，只能按已确认的原字符串变换和解析行为设计。传输码的字节数不代表显示宽度；在度量与绘字边界恢复同一完整 UTF-8 内容。不能用 strlen×字格宽、字符数乘字高或固定汉字宽替代真实度量。

度量和绘制共用字体身份、字号、hinting、参考包络和实际目标密度。整串自然宽度保留空格和原生排版所需的前进量，不以裁掉透明边后的墨迹宽度代替。由已确认的坐标换算把实际像素宽度交回原生逻辑单位，再由原生 UI 决定居中、折行、按钮尺寸及光标推进；不在 Mod 中保存另一份布局结果。

现有静态记录确认 0x10E5A0 中的完整串输出调用进入 0x10DDB0，后者原实现按字节取字形；同一原生流程还执行颜色、描边和光标操作。度量替换必须同时覆盖已经确认的整串、段落词宽及光标推进边界。具体指令依据见 [原生 UI 边界记录](evidence/rebuild-ui-boundaries.txt)，其中旧内容记录和复制重放方案不属于本规范。

## 字体与后端

使用 Windows 安装字体 Microsoft YaHei Bold 的 msyhbd.ttc，使用粗体文件的原生字面。固定 collection face index 为 0，SDL_ttf 样式为 regular，hinting 为 TTF_HINTING_NORMAL；不额外叠加模拟粗体。不复制系统字体，不新增字体包，不扫描其他字体或建立自动回退链。

使用游戏实际加载的 x86 SDL2 和对应 SDL2_ttf。本机静态依赖记录为 SDL2 2.30.0、SDL2_ttf 2.20.2，见 [本机分析](game-analysis.md)。字体身份包含实际文件内容身份、face index、样式、hinting 和后端版本，不能用文件名、字体对象地址或“微软雅黑”名称代替完整身份。

TTF_OpenFontIndex 的字号参数是名义 point size，不是可见中文高度。“9 逻辑像素字面上限”不能直接实现为名义字号 9。必须通过实际光栅结果校准。

使用 TTF_RenderUTF8_Blended 的灰度 alpha 抗锯齿，不使用 Solid 单色边缘或 LCD 子像素颜色。该整串接口本身不负责段落换行；原生 UI 决定拆分和调用顺序，Mod 对每次完整文本调用绘字。

接口与原点行为以锁定版本的 [SDL_ttf 2.20.2 源码](https://github.com/libsdl-org/SDL_ttf/blob/release-2.20.2/SDL_ttf.c) 为依据。既有静态定位包括 GlyphMetrics32、Size_Internal、Render_Internal 和 RenderUTF8_Blended，不假定其他版本内部行为相同，也不把内部 xstart/ystart 当成公共导出接口。

## 固定参考集与字号校准

固定参考集至少包含“国田永高汉翻译Agjpqy0123456789_|()[]”，同时纳入 ASCII、当前使用的中英文标点和当前已提交词库的完整字集。参考集不能只取本次正在绘制的一行，否则不同汉字、英文升部或降部会改变字号和基线。

对同一原生文字样式和目标密度，使用同一字体配置光栅化候选字号，读取实际非零 alpha 墨迹，形成完整参考集的稳定包络。TTF_FontHeight、ascent 和 descent 用于解释字体指标，不能单独代替可见中文高度或实际墨迹包络。字号选择取同时满足字面预算和完整包络约束的最大合格字号。

当前已确认主界面文字载体为原生 8×10 字格，约束高度为 10 逻辑像素。正文可见字面以 9 逻辑像素为上限，完整稳定包络及原生描边都必须容纳在原生 10 高约束内。9 是上限，不要求填满；描边可能使最大合格字号的可见字面小于 9。不能借用菜单选择框高度扩大字格，不能另造 10+2 行槽，也不能凭页面坐标给页脚或版本增加空间。更大的预算只能来自后续反编译确认的真实原生文字区域。

物理预算由当前已确认目标的真实坐标变换取得。文字高度上限按垂直密度换算；完整包络必须落在原生文字区域转换后的像素边界内。不能通过拉伸、压缩字形位图满足预算，也不能为某条长文本临时减小字号。

校准只随字体身份、完整字集、原生文字样式或实际输出密度变化而失效。同一组文字复用稳定结果，不在每帧或每条文本调用前重做全参考集校准。词库更新必须先取得完整已提交字集，再一致地更新度量与光栅所用的校准结果；不在同一原生绘制事务中混用新旧指标。

## 包络、基线与自然宽度

字体服务需要区分以下度量；距离注明属于实际光栅像素还是原生逻辑单位。

| 度量 | 用途 |
| --- | --- |
| 名义字号 | 实际传给 SDL_ttf 的 point size |
| ascent、descent、font height | 解释字体排版指标与基线 |
| 实际墨迹矩形 | 完整光栅中的非零 alpha 区域，不包含透明边 |
| 稳定上下包络 | 相对共同基线的完整参考集范围，含当前原生描边预算 |
| 完整串自然宽度 | 返回原生 UI 的排版依据，保留空格语义 |
| surface 内基线与裁剪偏移 | 透明边裁剪后恢复本次原生调用的正确位置 |

同一原生文字样式使用共同基线关系。不能对每条文本的紧包围盒分别居中，否则中文、拉丁字母和带降部字符会发生基线跳动。基线补偿来自稳定参考包络与原生调用的文字原点契约，不能来自 Mod 行槽表。

TTF_SizeUTF8 的完整串宽度与 TTF_RenderUTF8_Blended 使用同一字体状态。完整 surface 已包含 SDL_ttf 对负 bearing 的补偿；不能又用首字 bearing 重复移动整串。必须明确原生 x 表示排版框左边、pen 原点还是中心锚点，并依据已确认的调用契约转换。居中使用原生提供或原生计算得到的锚点，不写死中心坐标。

只裁去完全透明的边，不裁掉非零 alpha、描边或英文降部。裁剪后保留相对完整 surface 的偏移。若本次接口已确认为完整排版框左边及目标基线，则提交位置满足：

    dst_x = native_box_left + crop_x
    dst_y = native_baseline - baseline_in_surface + crop_y

这是同一次文字调用的原点补偿关系，不是页面排版规则。不能仅以 TTF_FontAscent 推测实际 surface 基线而忽略 SDL_ttf 的原点补偿；应结合锁定后端的字形指标、整串尺寸计算和实际 alpha 包络。

原生 0x10E5A0 已有四次偏移描边和一次前景的调用顺序。拦截这些调用时保留各次实际坐标、颜色与裁剪，不能按文本相同去重，也不能再额外画一组描边。描边角色用于共同字号和包络预算，不改变原生调用次数、混合次序或淡入颜色语义。

## 实际输出密度与即时绘字目标

高清要求是：从字体轮廓按实际输出像素密度生成字形，并以源像素与目标像素一一对应的尺寸提交。Nearest 只能控制采样，不能把低分辨率字形变成高清。先在 1× 软件面绘字，再随整幅画面放大，不符合该要求；先生成高清字形再缩小烘焙回 1× 软件面也不符合要求。

密度必须来自本次已确认的原生目标及其到最终输出的实际变换，不能仅使用窗口尺寸、Windows 缩放百分比或假定 renderer 当前目标就是最终输出。目标是 texture 时，应区分 texture 物理尺寸、当前 viewport/scale 和后续原生复制关系；原生软件面也必须确认其上传及复制链路。

已有静态证据表明软件路径 0x10AF90 从全局 RVA 0x61BBB10 取得 surface 像素和 pitch，上传至原生纹理后，以 NULL 源矩形和目标矩形调用 SDL_RenderCopy。原生 renderer 路径 0x10B480 也复制完整原生纹理。它们说明已有画面如何进入输出 viewport，**不证明软件面的文字已经按最终密度生成，也不授权在该复制处重放文字**。详见 [输出映射静态记录](evidence/font-rendering-static.txt)。

原生软件面扩展必须以目标创建、尺寸及 pitch、坐标与裁剪变换、实际写入和复制消费者，以及覆盖、重绘与销毁边界为依据，不能只改宽高或切换某个 renderer 标志就宣称完成迁移。本轮已确认边界见 [原生高清目标记录](evidence/20261019-native-hd-target-boundaries.md)，源码、编译与正式迁移状态分别见 [交付记录](evidence/20261019-native-hd-delivery.md)。

尚未取得这些证据时，应明确记录高清接入未完成，继续确认原生目标扩展接口。不得以最终 RenderCopy 重建整幅源、Present 叠字、另一套 UI 或 1× 放大填补缺口。本规范不虚构一个现成的目标扩展接口。

在已确认能原尺寸接收字形的原生目标上，位置采用该调用的实际坐标变换，提交尺寸与字形光栅尺寸相同。非等比的背景变换不构成横向拉伸字形的理由；自然宽度须以已确认的坐标关系交还原生 UI，而不能由 Mod 另排页面。

SDL 输出像素不等于经过 Windows 合成后的显示像素。2026-10-19 用户原图中的 1.5 倍重采样、DPI-unaware 游戏窗口及显示器 150% 缩放共同确认了系统位图放大问题。根启动器须在创建游戏进程前设置其继承环境 `SDL_WINDOWS_DPI_AWARENESS=permonitorv2`，由游戏实际加载的 SDL 2.30.0 在视频初始化、窗口创建前消费。保持 `SDL_WINDOWS_DPI_SCALING` 的既有默认像素坐标语义，不通过修改逻辑尺寸或输入映射补偿；既有字形路径随后按原生实际目标密度生成字形。字体代码和热更新不在已创建窗口中改变进程 DPI 策略。证据、上轮 100% 排除结论的更正及源码/交付状态见 [DPI 启动修正记录](evidence/20261019-font-dpi-startup.md)。

## SDL 状态与资源生命周期

字体库、字体、Mod 临时 surface 和 glyph texture 的创建、使用与释放发生在游戏绘制所属线程。模块入口或启动器的远程初始化线程不提前创建这些资源。对象由同一个游戏 SDL 实例创建和释放，不另载一份 SDL2 混用分配器，不释放游戏持有的 renderer、surface 或 texture，也不调用游戏全局退出流程。

即时绘字借用当前原生目标和本次裁剪。只临时改变已确认必须改变的 SDL 状态，并完整恢复。不得清除宿主 clip 后按 Mod 页面区域重新裁剪，不修改 logical size 或输入坐标映射来迁就字体，不改变原生背景和缓存的创建、覆盖、复制、重绘与销毁决策。

SDL2 2.30.0 的 scale、viewport 和 clip getter 有坐标换算关系；保存和恢复不能假定这些接口都返回物理坐标，避免非整数倍率往返取整损失。具体依据见已记录的 [SDL2 2.30.0 渲染实现](https://github.com/libsdl-org/SDL/blob/release-2.30.0/src/render/SDL_render.c)。采用哪一段状态借用代码仍须匹配已确认的当前目标，不能将旧 Present 合成流程移入即时绘字接口后继续沿用。

字体度量和光栅缓存以字体身份、字号、hinting、完整文本及影响字形的样式为键。GPU glyph texture 还受 renderer 身份约束。缓存可以保留透明边偏移等字形自身指标，不能保存 UI 位置、控件裁剪、页面次序、原生覆盖历史或可供再次绘页的命令。

缓存有明确容量和失效边界，不无限保留历次密度、词库代数或文本。字体身份、字集或密度改变时清理不再适用的缓存；原生 renderer 销毁时释放与其关联的 Mod texture；业务模块退役时在旧映像仍可执行清理的阶段释放其字体和图形对象。跨模块代数只传字体配置、内容身份等纯值，不保留旧 TTF_Font*、SDL 对象指针或回调，也不序列化文字位置供新模块重放。

## 职责、证据与交付

原生组件适配负责已确认文本读取、格式化、度量及绘制边界；语义与词库负责完整中文内容；编码扩展只解决已确认原解析路径的文本传输；字体服务负责真实度量、稳定校准、即时光栅和字形资源。Host 负责通用调用、模块生命周期和发布事务，不收集界面文本，不保存页面布局，不调度 Present 绘字。此处不重新定义 Host ABI 或设置界面快照协议。

- [本机分析](game-analysis.md)：游戏版本、依赖和已定位的文字候选路径。
- [原生 UI 边界记录](evidence/rebuild-ui-boundaries.txt)：完整串调用、原生描边与度量指令；其中全局像素 Hook、内容记录和复制重放条款不适用。
- [输出映射静态记录](evidence/font-rendering-static.txt)：软件上传、原生复制参数和 DPI 元数据；不证明高清目标迁移已完成。

发现代码或旧文档与本规范冲突时，记录具体位置、影响和待整改状态；不能因为已经编译或正式发布就认定符合要求。源码修改、产物编译和正式文件发布分别记录。

不启动游戏、注入游戏、模拟操作、运行产物或测试，不写测试用例、测试脚本或断言，不增加基于假设的补偿分支。编译仅通过项目统一队列生成交付产物。静态依据、规范和编译结果均不能替代用户实际运行反馈，也不能把仍待确认的高清接入写成完成。

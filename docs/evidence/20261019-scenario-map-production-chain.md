## 本轮结论

当前介绍页正在消费**尚未生成有效地图内容的缓存**。地图图集已经加载，但地形与人物尚未绘入地图；地图层开关 `61BBCD8=1` 却令最终呈现继续复制两张地图纹理。实际复制使用 `blend=0`，因而缓存中的黑色直接覆盖介绍页。

这比上一轮只定位矩形更进一步：已把异常限定为“地图生产尚未完成，地图消费却已开启”，而不是地图正常画好后被中文文字变成黑色。**首次把地图开关设为1的历史写者仍未确认，不能据此宣布汉化归因已证实。**

## 正常应该显示什么

介绍页 `FB390/FB7D0` 的原生构建是：全屏渐变背景、情境标题、右上 `terrain-village.jpg`、左上说明、下方人物故事、底部继续按钮。它没有为 `{15,85,450,460}` 留出地图区域。当前地图矩形跨越说明、故事和照片左缘，不是本页设计的黑色面板。

进入实际游戏后，地图源才应包含角色附近的地形、物体与人物图块，例如已加载的 `ter-birch`、`ter-boulder`、门、家具及 `cur-pcdirs`。黑色在地图生产中用于清空底图，并可用于无内容区域；整块遮住介绍正文不是该页的正常内容。

## 为什么形成当前黑块

1. 介绍页尚未返回，正常的角色周边地图生产尚未完成；当前绘制矩阵、可见性和图集提交标记与此一致。
2. 当前 `61BBCD8=1`、呈现未被抑制，使 `D3C80` 在上传已经画好的介绍页之后继续进入 `110040`。
3. 颜色三标量全0，当前走地图纹理复制分支，不是 `110096` 的黑色矩形填充支。
4. 空地图缓存被复制到合成纹理，再以不混合覆盖方式送到地图矩形，出现截图中的整块黑色。这里的异常是**提前消费地图层**；不能把尚未查明的缓存初始像素来源写成已经实际执行了清图函数。

## 仍待确认的边界

- 地图开关1的具体历史写者。正常创建时 `1304B` 清CL再调 `10D40`，不会执行 `11112` 的参数非零分支。完成页／世界页重绘未发现漏掉已存在的地图开关恢复；原生临时地图显示 `F6510` 的保存/恢复也完整。
- `FIRST TIMER INFO` 的 `DF7B0` 只有原生 `5F8FABC!=0` 分支才会在 `DF907` 设1；当前为0既不能证明执行过，也不能排除它曾执行后被清除。
- 窗口事件 `D1E99 → 10ADB0` 会销毁重建地图纹理，Mod随后重画介绍正文却不生产地图，是另一条可导致空缓存被消费的候选链。但本次没有历史窗口事件记录，且当前所有图集均未提交，更直接的证据指向当前地图本来尚未生成；不把候选当作本次已证实事件。

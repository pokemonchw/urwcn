# HUD、消息分页和地图的原生重建边界

证据来自 3.89.1 原 PE 的离线反汇编；本次没有启动游戏、模拟输入、运行测试、编写测试或断言。本文 RVA 均以原 PE 的 0x400000 基址为准。

`modules/adapter/native_hud_language.inc` 重新进入完整原生构建函数，原生 UI 继续处理面板、文字位置、纹理、控件及缓存。它没有调用 Scene paint、renderer owner children paint，没有保存页面内容/像素/绘制贡献序列。序列化保存 Command 组件被接受的原英文输入、地图原输入协议的阶段/选中项、目标选择组件在同步原构建阶段使用的原标题与真实选择输入，以及下述单个 FAA30 Widget 的真实逻辑输入。

## 完整 HUD 与业务副作用切分

主等待 `17D0A6→D3BF0` 消费语言返回后，把已消费的返回值设为原无动作值0；因此原 `17D0BD` 不再把 `-2` 送入 `17D0C2→99BE0` 的世界/可见性业务重建。Host 的 CALL After 只回写寄存器，不采纳 `resume_rva`，这里没有依赖 After 跳转。

- `FA2A0` 完整构造右侧原生 HUD，保留 `FA2FB→12980` 原生背景图。`FA305` 完成原来的 14h 栈清理后，在 `FA308` 跳到 `FA34E`，避免重新建立/清空实际消息组件。`FA2E7/FA2F1` 的消息完成位置清零也只在语言构建中跳过。
- `FA353→F90D0(INIT)` 仍完整构造 Command 标题与底色。之后用该组件的真实原英文构造输入重新进入完整 `F90D0`，恢复其当前命令内容。`F90E4` 的普通调用保存输入；普通 INIT 按原控件清除语义采纳空英文。主输入 `17D0A6` 的输入由此前必经的 `17D014` 空命令构造确定。
- 完整 `F9600(0)`、`F9200(0)`、`F9910(0)` 都执行，不能仅清空面板并重画标题。`FA749` 跳到已平衡的 `FA794` 返回，跳过不属于文字构建的上传、淡入淡出和光标操作。
- `102D10`、`FF040` 和 `103640` 分别重新读取现有惩罚、饥饿与时间/季节字段并完整显示。不执行此前的 `1032C0→84DF0` 业务更新。
- `8FF70` 完整构造现有地点、区域、日期、地图类型和比例尺。它用 RVA `1E2C20` 缓存原英文位置 key，`8FFE5` 的相等分支会跳过整段已接入文字，因此语言构建只绕过这个原 UI cache-hit 判断，执行原生完整面板、日期和标尺生命周期；普通路径仍按原比较结果分支。`10B320` 是原生命名 UI 资源的销毁函数，位置/日期查询不调用游戏业务更新。
- `F9200` 的 `F92D0/F9422/F9459/F94BA` 盾牌 bit0 写入只在语言重建时跳过，原有显示分支、后缀及道具行照常执行。
- `51770` 特殊道具名称通过 `CB20` 复制原 NPC 记录到第499槽，然后写该槽 +67h 并调用 `AE750(499)`。原副作用涉及完整 568h 字节，不能仅跳过一个字节写入。重建在同步调用期间借用并恢复这个确切的名称格式化工作记录，位置为 RVA `5DF9DB8`；没有保存 UI 布局。`AE750` 的可选 `AE7B6→AECB0` 调试业务路径被跳过。

## FAA30 的完整发布与构造中途输入

`FAA30` 的两个真实速度查询 `FACFD / FAE71 -> DB960(-1)` 均可经 `927E0` 调试路径、`92928 -> F6510` 到达 `F5B00` 分页等待。这发生在 `FAEFF` 数字构件被接受之前，尤其第一次 FAA30 尚无任何完整数字源。此前直接查 `FAEFF` 模型的实现已移除，不能将尚未构造的数值当作空字符串。

新增单个 `WidgetInput` 只在原生真实消费边界接受逻辑输入：

| 原读点 | 原逻辑输入 |
| --- | --- |
| `FAACA` | byte `A32B054` 动作模式 |
| `FAAEB` | byte `61A9DAF` 隐藏状态 |
| `FAB22` | byte `53908FB` Fallen/Sleeping 分支输入 |
| `FAB91` | byte `A32BCE6` 移动方式 |
| `FAC48` | dword `A3840E4` Hiding 分支输入 |
| `FACA1 / FAF3B` | dword `A384110` 的实际方向输入 |
| `FAD61` | dword `A2D0AF4` 原单位选择 |
| `FAE3D` | byte `A32B1AF` 原颜色比例计算输入 |
| `FB060` | 原八方向活动 timestamp `61A8CC4[ESI]` |
| `FB115` | dword `A32B180` 原活动年龄时钟 |
| 两个 DB960 CALL After | 各自真实业务查询返回值 |

没有保存样式、调色结果、已格式化数字、坐标、输出行、字形、帧指针或像素。常量调色、原字体与布局继续原读；两个原查询以外的 sprintf、单位换算、原色阶函数和图标年龄计算都继续由完整 FAA30 构造完成。时钟读之后不存在写时钟的路径，活动循环也没有输入等待，因此一个真实原时钟值覆盖其完整循环。源只按原执行到达的分支消费，尚未到达的数字输入不会被读取。

普通 `FAA4B` 开始 working 输入；两个真实查询 CALL Before 分别标识构造阶段 1 / 2，实际 CALL After 接受返回值并结束该查询阶段。只有原 `FB239` 完整 software surface 复制与 `FB242 -> 116E20` 的 `headingicons` 命名纹理发布完成后的 `FB247`，才提交完整 published Widget 输入。原 `10C400` 接受新 software-renderer 目标时，清除该资源之前的 published / working 生命周期。保存接口把这两份完整组件逻辑输入、真实发布状态和当前查询阶段追加进现有 HDA8 第18节，不增加全页模型或新分节，也不承接旧 schema。

语言重建先用完整 published 输入重新执行 FAA30：两个 DB960 只注入各自真实原返回值，原格式化、单位、颜色数学、表面发布、`headingicons` 工厂及其四个原生矩形写入全部保留。普通游戏字段不写回；`FAC79` 隐藏标志清零与 `FB128` 过期活动清空在构造期跳过。若原第一个 Widget 尚未发布，其明确未发布生命周期不构造一个假组件。

若当前实际查询仍在调用中，随后在同一真实 working owner 上重建原阶段前缀：阶段1跳过未返回的查询，在 `FAD07` 给原 `SUB ESP,8` 作 8 字节清理后转 `FB250`；阶段2在 `FAD07 -> FAD3C` 平衡原栈，`FAD3F` 只进入已接受的原单位常量分支，再于 `FAE47` 清理仍存的 8 字节并转 `FB250`，没有制造数值缓冲。前缀均在 FB239 之前退出，因而不发布半成品，也不清掉刚重建的完整 `headingicons`。

前缀退出继续原 `FB255..FB257` 三个 POP，在 `FB258` 跳过仅属于完整缓存发布的四个矩形写入，转 `FB27F` 原 cookie / epilogue。完整 published 构造仍保留这些 UI 缓存矩形写入。原对齐帧的三个保存寄存器与 cookie 全部平衡；原活跃 FAA30 / DB960 帧及唯一业务查询仍在消息等待返回后继续，使用已恢复的新语言 working 前缀。它不重跑雪地 PRNG，不提交新的业务消息。

新增 hooks 为 `5291..529B` 与 `529D..529F`；`FAA4B` 复用原 `hud_target_entry=630A` 观察输入后继续原 `promote_hud`，`FB115` 复用原 `activity_age=5A05` 观察 / 借用时钟并继续原图标 consumer，不安装重复 site。既有 `speed_stack / speed_value / speed_color` 只负责上述三个确切原生切口。比较 operand loan 只保留实际后续 `JE/JNE` 消费的 ZF，移动 operand loan 只写原目标寄存器；没有改游戏业务字段。

另外两个实际显示 producer 也消费同一完整源：`hud_speed_number` 使用 `display_units()`，因此其 suffix 与原单位 formatter 的已接受输入一致；`native_hud_icons::borrow_direction()` 同步借给 `FAF04 / FB01C` 的真实 IconSource producer，其记录与原 `FAF3B` 绘制读取相同方向，纯构造不把借用方向写回游戏字段。该指针只覆盖一次完整原 FAA30 调用，不保存进任何 payload；configure / restore / shutdown 均清除此同步借用。

## 实际分页等待与 More 缓存

英文消息中的中文姓名使用同一完整 `F6510` 消费范围。`windows_messages::borrow` 从已接受消息的完整原 UTF-8 输入判断 Unicode 需求；编码时以同步 `UnicodeMeasure` 提供原生传输，随后将同一个 Unicode 字形/度量范围交给该 Display 自身的原生命周期，直至 `finish`。因此原字符拆分、单词容量、换行、光标推进和最终即时字形消费同一种编码与字体。原低字节/Nordic 输入不靠高位字节猜测成 Unicode。

实际分页续点的 `transfer_display` 同时移交这个 Display 对应的 Unicode 范围与其 Host 文本缓冲；原等待由实际原帧继续。`finish` 用同一个借用 token 清理完整调用的范围，没有新增页面快照、延后绘制、Display 内存格式或序列化格式。先前英文分支在临时编码范围结束后按字节处理中文姓名的缺口已整改。

`native_message_flow::paint` 消费完整原生消息组件的已接受记录，通过原 `F6510` 重排，并把新的解析位置交还给原来实际挂起的 `F5B00`。当前消息组件重建后，消息自己的行位置与计数输入更新到新的原生结果；调用者通用光标仍按既有调用协议恢复。

`F5BCE→D3BF0` 收到语言唤醒后，在实际 `F5B00` 帧上借用 `F5B7F..F5BB8`。这段执行原 `10C540`，更新原 named More 背景，然后执行完整 `114680` 控件；到 `F5BB8` 时同步返回。原循环继续拥有等待与上传，不能把原 ACK 当成已发生。

原 PE 有48个直接 `F5B00` 调用：`F6A38/F6C4F/F6D11` 三处是 `F6510` 的分页，其余45处调用均在前面显式写 counter=100 和 ECX=0。`F6510` 内没有 counter 赋值；`F5BAE` 在显示控制后清零。因此当前记录的 entry.counter=100 且 acknowledged=0 精确对应第一次 Continue，其后是 More。这个输入已经在原 HDA7 消息记录中，已打开的旧等待不需要猜测控件文字。独立45处使用其确切 Continue 输入，并把重排结果交还实际等待自己的光标续点。

`F5A30` 的独立空格/ESC窗口也按完整原构造重新保存 first 并构造原按钮，跳过新输入循环及淡入淡出；原实际输入帧保留，退出时的 `10DA60` 使用已更新的真实 first 缓存。

## 已知区域地图的实际原帧

`E5990` 入口有音乐、地图业务输入初始化等操作，不能直接重跑。实际 `E5F59→D1120` 的返回点是 `E5F5E`。共同输入收到 -2 后先通过原 `D19B3` 平衡退出 D1120，再在原地图帧的 `E5F5E` 转回 `E5AC0`。恢复真实 SDL_SetRenderTarget 函数输入，沿原 `E3D90/E3EE0` 全工厂、原 Menu、控件、地图、标记和上传路径重建，保留当前地图滚动/视图本地变量。到下一次原输入前恢复原选中项。

second 的全部恢复统一在真实复制完成、栈参数已清理后的 `10D3BA` 与 `10D44A` 消费语言 revision，包含 `10D420` 的七个 caller（`E9B70/FEDDA/103A17/108B2D/146469/147111/17DF35`）与 `10D3A0` 的四个 caller（`E9B77/15D6D5/17D9AA/17D9C0`）。原拷贝已经还原真正父场景像素并激活其源身份，然后完整构造父 HUD、调用原 `10D340` 重新保存 second；仅在同步保存时通过 `10D350` 跳过“缓存已有”判断。原恢复函数继续自己的 flag、上传、淡变与呈现。不能在 `17DF35` 之前拿尚未恢复的地图当成父场景底；本次已将该早期方案替换为上述两处共同边界。没有手造缓存、替换像素或 replay 页面。

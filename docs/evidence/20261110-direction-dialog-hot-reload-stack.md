## 原指令证据

对象与哈希同[全部文本提取](20261110-direction-dialog-all-text.md)。下文使用 RVA，完整原指令在[窗口反汇编](20261110-direction-dialog-native.asm)。同一个真实原生 `ESP+24h` 在不同阶段有不同语义：

| 阶段 | 原指令 | 栈槽内容及消费者 |
| --- | --- | --- |
| 首次构建 | `F7843 MOV EDI,EDX`，`F784F MOV [ESP+24h],EDI` | 原调用者英文标题指针，两处实际构建输入之一 |
| 标题 | `F78FC MOV ECX,EDI → F78FE D3DB0 → F7918 116270` | 从 EDI 取英文标题，转大写副本并画原生面板 |
| 动作正文 | `F7AD0 PUSH [ESP+24h] → F7ADE 10D0` | 原 `Select %s` 把栈槽解作字符串指针，构建到原临时缓冲 |
| 输入循环 | `F7CF7 MOV EDX,[65BBCD8h]`，`F7CFD MOV [ESP+24h],EDX` | 已复用成保存原显示浮点值的4字节槽，供 `F7D26/F7D30` 原样恢复 |
| 语言唤醒 | `F7DD4 D3BF0 → F7DD9` | 原等待返回 -2，既有完整语言重建回到 `F78B1` |
| 实际用户选择 | `F8393/F8399`、`F84D5` | 该槽还会在原业务后段复用为世界坐标／边界值，不能视为持久标题 |

既有 `native_hud_language.inc::target_result` 会从真实活动调用者恢复 `target_heading`，重建父背景，把 EDI 设为恢复的英文标题，再跳回 `F78B1`。它漏掉了 `F784F` 所定义的另一个必要输入。截图中关闭门的原模式 `06h` 先走标题，再走 `F7AD0/F7ADE` 的动作正文；旧栈槽此时是上述浮点位模式，原 `%s` 会将其当作地址解引用。

这一缺陷与标题翻译、分词器、字形绘制无关：新增 `F7AEF` 消费发生在原 `%s` 格式化之后，无法补救错误指针。首批静态审阅未闭合重建片段的全部栈输入，是这次交付的漏项；先前文本提取文档把该重建路径视为完整的结论在此纠正。

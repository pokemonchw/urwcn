Progress display ABI, color and final presentation
--------------------------------------------------
123DF0 saves the incoming display pointer in ESI and calls SDL_FillRect through
IAT 18C1E8. Its rectangle constant at 1DD8A0 is four int32 values:
    {5, 30, 396, 11}
It computes the native byte-string length and, for length > 80, writes NUL at
display[70]. This is the game's existing mutation; translating the input
buffer would also change native log content and is unnecessary.

123E46 PUSH 0 is the outline argument, retained below the RGB call arguments.
123E48, 123E4D and 123E52 each PUSH AB.
123E57 PUSH [surface+4] supplies SDL_PixelFormat*, then
123E5A calls SDL_MapRGB through IAT 18C1F8. Therefore the resulting text color
is RGB ABABAB (171,171,171), not a palette-index guess.
123E63 EDX = 30
123E68 PUSH EAX (mapped color)
123E69 PUSH ESI (original display text)
123E6A ECX = EDX-20 = 10
123E6D E8 2E A7 FE FF -> 10E5A0
123E72 ADD ESP,0C
The established native text ABI is ECX=x, EDX=y and three stack arguments:
text pointer, mapped color, outline. The caller removes 12 bytes.

The existing software-frame branch then uses 123E7E ->10AF90, conditional
native drawing work, and 123EA3 ->10B3C0. If the original present condition
selects it, 123EB1 pushes the renderer from A2110CC, and:
123EB7 FF 15 7C C2 58 00 83 C4 04
calls SDL_RenderPresent via IAT 18C27C and removes its single argument.
The Present call and ADD ESP,4 remain original. The adapter uses the exact

string belongs only to that 123DF0 invocation; 123E6D borrows it as the text
argument to the original 10E5A0. ECX/EDX, color and outline remain native.
123DF0 itself still receives its original English input and retains its clear,
byte-length mutation, conditionals, log output and return effects. No decision
is made from a generic SDL call or the final formatted English sentence.

Within the 10E5A0 call, existing complete-string 10DDB0 hooks immediately

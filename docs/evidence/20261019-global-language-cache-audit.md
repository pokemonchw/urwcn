# 全局语言切换：原生缓存与绘制记录静态审查

日期：2026-10-19（Asia/Shanghai）。目标为《不真实的世界》Windows x86 3.89 / Steam Build 25939378；原 EXE SHA-256 为 `e0b15bbbe16ffcd95d4ab61f08fe95dea4b95ebe1b3de428dae1d9477a9710d9`。本文使用 RVA，附属反汇编使用首选基址 `0x400000` 的 VA。

仅阅读源码、已有反编译和离线 EXE 反汇编；没有启动游戏、注入、模拟输入、执行测试、编译、运行产物、编写测试或断言。没有新增汉化运行逻辑。附属原始指令见 `20261019-global-language-cache-disassembly.txt`。

## 可实施结论

普通输入 `D1CD4` 和动画输入 `D26AB` 已经是统一快捷键消费边界；全局语言值可以统一切换。当前原生缓存没有一条已确认的接口能把所有已绘位图重新生成为另一语言。`10ADB0`、`10AF90`、`10B480` 与 `10B3C0` 均不能充当这个接口。

游戏自己的 `10B3C0` 绘制记录确实保留少量原生 caption 的文本与几何，可以在该真实原生 caption 消费处统一选择显示语言。它没有保存软件页面的全部文字，也没有保存所有 HUD 文字；不能据此声称任意当前页面能够即时切换。把 Mod 绘制历史加入该表或另建文字/坐标序列，仍会引入 AGENTS.md 禁止的贡献重放机制。

若继续实现全局即时切换，需要继续确认一个包含当前原生 UI 完整内容且不重执业务的重建边界，或修改原生共同组件，使其保留并管理自身语义。仅抽取现有逐页 pending/continuation 到统一表，不会补出这个缺失的原生边界，仍然是逐页重建。

本轮用户要求的是共同机制下快速切换当前画面，现有逐页刷新不作为完成方案。原生共同组件的进一步调查见 [公共组件记录](20261019-global-language-components.txt)：当前菜单表可复用，但共享段落词槽被后续段落覆盖；按钮与独立标题的参数只活在本次原生栈帧。因此，组件级语言资源绑定是需要继续确认的架构方向，尚无覆盖这些路径的合规实现，不能把这一方向写成已找到可直接实施的完整办法。不能通过 Mod 新建整页语义快照、重建组件树或文字贡献序列来填补缺失的原生所有权。

共同机制的完成条件是：一次真实快捷键切换使所有已接入的当前可见文字及其原生缓存按所选语言重新构建，原生度量、换行、按钮和命中同步使用新文本；保留选择、输入内容、滚动、世界和角色状态，不重执配置、随机数、音乐或退出业务。不以等待重新进入页面、模块 Applied 或新增一个统一函数名代替这个结果。本次没有达到该条件。

## `10ADB0` 只重新建立两个纹理

完整函数 `10ADB0..10AE74`：读取 `61BBD14`，非空时调用 `SDL_DestroyTexture`；随后 `10ADED` 调用 `SDL_CreateTexture(renderer,0x16362004,2,1800,1800)` 并写回同一全局。对 `61BBD04` 重复这组流程，创建调用为 `10AE3F`。两处失败分支只有 `SDL_GetError` 和原字符串格式化。

函数中没有 `10E5A0`、`10E260`、`10E3E0`、`CFFB0`、`162300`、`10EB40` 或 UI 构建调用，也没有当前页面识别或语言状态。`D1E99` 只是窗口事件在 resize/size_changed/maximized/restored/moved 分支调用它。重新建立纹理不等于重建已在 surface/texture 中的文字。

## `10AF90` 和 `10B480` 只合成已经存在的内容

`10AF90..10B036` 读取主 surface `61BBB10` 的 `pixels/pitch`，`10AFB6` 调用 `SDL_UpdateTexture(A1C2020,NULL,pixels,pitch)`；随后清当前 renderer，`10B00C` 将原 texture 复制到 renderer。没有字符串构建或解释；源 surface 中已绘的语言直接上传。

`10B480..10B64F` 清主 renderer，`10B4FA` 复制 `A1C1CBC` 指定的原缓存纹理。只有当原生 `A1C2010 & 0x10` 时才在 `10B508` 调用 `10B3C0`；其余位分别控制原生地图/视图、图片与光标等合成。不能把 `10B480` 直接调用理解为“全部控件和文字重新运行”。

`D1E41→10B480` 后在 `D1E70` 呈现；另一分支 `D1F19→10B480` 后在 `D1F48` 呈现。软件分支 `10B720` 在 `10B72A` 调用 `10AF90`、`10B74F` 调用 `10B3C0`、`10B763` 呈现。它们都可能把已有像素重新提交；全局触发这些呈现不会改变 source 中已烘焙的文字。

## `10B3C0` 原生记录的精确范围

`10B3C0..10B479` 从 VA `A78521C` 开始遍历，步长 `C48`，终止于 `A7E761C`。这是表 RVA `A3849F8`、128 个条目的 `+824` 字段；表末为 `A3E6DF8`。每个条目属于游戏自己的图片/overlay 管理，不是 Mod 记录。

| --- | --- | --- |
| `+0` | `SDL_Texture*` | `10B3E0` 读取；`116D8D`、`116F08` 写入 |
| `+4` | 原生名称字符串 | `116C59..116C9D` 查找已有槽；`116DB6..116DCB` 复制名称 |
| `+804` | 原生组名/分类字符串 | `116DE6..116DFB` 复制；`10B268..10B2BF` 按此清理 |
| `+824..+830` | 原生目标矩形 | `10B3F0..10B415` 读取；首字段为零时使用游戏默认矩形 |

| `+838` | 原生图片呈现参数 | `10B418` 传入 `113200`；`116E06` 写入。不把未知整体语义擅自扩展成文本样式 |

每个可见且 texture 非空的条目先由 `10B41E→113200` 绘制图片；caption 非空时才由 `10B44F→10E3E0` 绘制。没有 panel、menu、button、paragraph 类型分派，也没有通过条目重新运行调用者页面的代码。

`116C10` 是原生图片加载/登记路径：按名称寻找已登记或空槽，加载图片 `116D48→IMG_Load`，`116D7A→SDL_CreateTextureFromSurface`，写入纹理、名称、组名和参数。它没有读取任意页面的完整文字，也没有从图片恢复文本。

`10B250` 按组名或全部清除纹理/槽；`10B320` 清除特定原生槽；`116FB0` 初始化表。它们没有负责重建被清文字的回调。清表会失去图片/overlay，不能凭此制造一个“让所有文字自动重新生成”的失效协议。

## 已确认的原生 caption 与未纳入的文字

现有完整 EXE 反汇编中，以表绝对基址访问 caption/其 x/y/颜色字段的写入集中在 `8FF70`（原反编译名 `world_bottom`）：

- 绝对基址搜索只说明该查找范围的结果，不据此排除未知间接指针写入，也不据此新增未知组件翻译。

## 输入唤醒也不提供完整 UI 重建

`D2083` 返回原生非按键 `-2` 是当前已确认消费快捷键的合法续接点，但它只通知外层继续。`D3C80` 在 `D3D0A..D3D0D` 对小于 1 的结果重新等待，没有重建调用者文字。`D1120` 使用已绘菜单缓存；其通用输入循环没有重新构建全部调用者页面。

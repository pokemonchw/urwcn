# MessageFlow 原生重建边界

> 历史调查记录。下文“当前未实现”“仅保存已译结果”描述的是开始 Message AST/Flow 改造前的状态。后续已实现的中性生产图、原生视口生命周期与完整 UI phase/真实等待 ABI 见 `20261020-native-message-flow-source-and-input.md`；本文件保留原始缺口和不安全重入依据，不作为现源码完成状态。

本轮仅静态读取已确认 PE，没有启动游戏、注入、模拟输入、测试或编译。地址均为 RVA，原函数反编译见 `settlement-ghidra.c` 的 `004F6510` 和 `004F5B00`；已有逐指令文件为 `build/windows-sync-pe.asm`。

## 完整 F6510 不能直接作为 locale paint

| 地址 | 已确认的原生行为 | 重入影响 |
| --- | --- | --- |
| `F65CD→162AC0` | `*` 消息键展开。 | 不是已完成中性正文的纯显示消费。 |
| `F65F2→15FB00`、`F6626..F6662` | 提取声音字段并从正文去掉该字段。 | 需要原真实字段来源，不能从已翻译正文推断。 |
| `F6664..F6723` | 大小写处理，并写 `1D7F453=0`。 | 再次消费/修改原构建状态。 |
| `F6734..F67A7` | 比较 `1E6AC0` 与当前英文正文，按 `61A8CBC` 抑制重复。 | 同条消息重入可能不画；强行改比较结果又会影响原业务语义。 |
| `F67B0..F67C1` | 更新最后英文正文。 | 不是独立 paint 的无副作用操作。 |
| `F6A38`、`F6C4F`、`F6D11` | 调用完整 `F5B00`。 | 可进入分页输入并设置 skip 状态。 |
| `F6DB5→B8D0`、`F6E3A→F5C50` | 显式声音或英文关键词声音选择。 | 再次发声；`F5C50` 的部分分支调用 RNG，不能重跑。 |
| `F6E68→10B720` | 原生屏幕提交及相关显示状态。 | 不是只重建组件缓存。 |
| `F6EB3→F6280` | 写英文消息日志。 | 再次追加历史。 |

当前借入区间 `F6A45..F6D8A` 仍包含两处 `F5B00` 和 `F6020`，并依赖完整 F6510 栈帧里的颜色、词缓冲、历史拼接缓冲和输入索引。不能将该区间视为现成独立 ABI，或猜初始寄存器后调用 native fragment。

## F5B00 是输入状态机

`F5B77` 比较原分页 counter；`F5B87→10C540` 保存实际区域；`F5BA9→114680` 构造原继续按钮；`F5BC6→10B770` 提交，`F5BCE→D3BF0` 等待输入。原 Space/ESC 分支在 `F5BD8..F5C09`，ESC 写 `619F958=1`；完成后 `F5C0E→10C690` 恢复区域。普通未分页分支 `F5C29..F5C2B` 递增 counter。不能以重建为由消费一次输入或重置这些原始状态。

## 当前旧正文并非内存消息队列

`F6020` 是原生滚动操作：`F6093` 以当前主 surface 为源和目的调用原 SDL blit，`F6112` 填充底部条；随后 `F6134` 写 x、`F6164` 写 y。它消费已有 UI 像素及真实原生消息矩形，未读取文本队列或可重建的旧记录。

`F6280` 是日志写入器：`F62D9` 打开文件，`F630D..F6431` 构建颜色、人物、位置等日志字段，`F646F` 及 `F64DD/F64E5` 输出，`F64E8` 关闭文件。它不是持有可见消息记录的原生缓存对象；日志也不等于当前可见消息的输入状态与控制语义。

目前确认的内存仅有当前正文 `61A84B8[400]`、最后比较正文 `1E6AC0`、词暂存 `61A96A0[400]`、cursor 与矩形，以及分页 counter/skip 状态。没有证据证明其中保留了所有旧可见消息的中性语义队列。不能扫描 surface 反建文字，也不能用逐字绘制贡献替代缺失的模型。

## 下一步必须确认的扩展契约

需要在实际共同消息 owner 的创建、清空、append、分页/继续和销毁边界扩展其自有中性记录，普通显示也消费同一个对象。每条应绑定实际英文消息及完整模板/参数资源，不能把现 `windows_messages::values` 的 `{英文结果, 已译字符串}` 快照直接当成中性构建源。

可研究完整 F6510 的明确 UI phase Hook 协议：完整函数保留真实局部帧，locale materialization 在已确认位置跳过输入、日志、声音、重复登记等业务边界，原生文字循环及滚动继续执行。但每项跳转的寄存器、局部变量、原输入 owner 状态与 cache/source 生命周期均须逐项闭合。当前未实现该协议，未创建猜测 queue、独立 UI 或 unsafe 重入；因此不能声称消息区已经支持当前可见旧正文的全局切换。

分页等待还有额外的真实输入状态：`F6C4F` 调用 F5B00 时，父 F6510 的 EBX 是当前显示正文索引，`61A96A0` 是正在检查的完整词；返回后 `F6C54` 和后续原分支继续消费这次父栈帧。`F6D11` 的尾词分页同样保留父帧局部数据。整段中文与英文的长度、词序和分页数可以不同，单纯重画所有记录后恢复旧 EBX，会让原等待返回后继续消费旧语言偏移。不能把该偏移直接解释为中性语义位置，也不能静默消费或跳过一次原 Space/ESC。

后续组件扩展需要把这个实际等待的原 UI frame、源 record 身份、原生分页状态及重新布局产生的恢复点纳入同一个 InputOwner 协议；原生函数继续产生恢复点，Mod 不按字形贡献或保存的输出位置推断。现 `windows_messages::values` 只保存英文最终值与已译结果，尚缺可重投影的模板键/实际中性参数图接口。该缺口与完整 UI phase/等待帧协议均未闭合前，本轮保留现消息业务源码，先完成 Menu/Flow InputOwner 分离。

已核对的现源码缺口为：`windows_message_formats::construct` 有真实 `Entry.key` 和 typed `Parameter`，但 `pending` 只保存翻译结果，After 仅调用 `message_bind_value`；`windows_message_resources::Text` 有真实 key/query，却在 tag/子查询展开后仅保留已译字符串；部分拼接构造同样只有 `Append::translated`。这些 dispatch 还在英文模式直接跳过。后续中性 source graph 必须在两种语言的普通构建中都记录实际选择的模板、实际参数及其嵌套资源身份，再由共享 projector 输出当前语言；不能从最终英文字符串猜模板，也不能用 `translated` 缓存替代参数模型。

# 原生公共 UI 组件扩展：所有权与 ABI 静态边界

日期：2026-10-19（Asia/Shanghai）。对象为《不真实的世界》Windows x86 3.89 / Steam Build 25939378，原 EXE SHA-256 为 `e0b15bbbe16ffcd95d4ab61f08fe95dea4b95ebe1b3de428dae1d9477a9710d9`。以下函数与数据地址为 RVA；附属反汇编使用 `0x400000` 首选基址的 VA。

本轮用户已授权 Hook 并修改原生公共 UI，实现全局快速语言切换。因此目标可以从“寻找原版现成的全局 redraw”推进到“扩展原生共同组件接口与对象生命周期”。这一授权不包含全局像素追踪、把字形调用保存为文字/位置贡献序列或在上传/RenderCopy/Present 时重放；也不允许测试、运行产物、注入游戏、模拟输入或猜测兜底。本子任务只保存静态证据与设计边界，不修改运行源码、不编译或发布。

## 新确认：游戏自己已经定义完整菜单模型的保存范围

游戏原代码成对保存及恢复两段原生对象数据：

| 数据 RVA | 长度 | 原生含义 |
| --- | --- | --- |
| `5F54A20` | `190h` | 菜单头、标题、布局/选中/颜色等原字段 |
| `5F4EF10` | `5AA0h` | 100 条原生菜单记录，每条 `E8h` |

这两个长度不是 Mod 从零散字段推导出来的结构大小：

- `F648/F64D→F652` 把 `190h` 字节头写文件；`F657/F65C→F661` 把 `5AA0h` 行数组写入同一文件。
- `F993/F998→F99D` 与 `F9A2/F9A7→F9AC` 从文件读回相同两段；`F9BB` 恢复原生当前选择，然后 `F9C1→F678→CFFB0` 重新使用这份模型。
- `D7BA3/D7BA8→D7BAD` 和 `D7BB2/D7BB7→D7BBC` 再次证明同样保存；`D7C1C/D7C21→D7C26` 和 `D7C2B/D7C30→D7C35` 读回；`D7C3E` 恢复真实选择。
- `docs/evidence/local-inspection.json` 确认 IAT `18C4D8=fwrite`、`18C4A8=fread`。保存期间使用原游戏文件，是原实现事实；扩展组件无需引入文件 I/O。

因此，公共 `Menu` 组件可以绑定一个游戏定义的原始英文模型，而不是收集每行字形绘制贡献。统一切换时让原 `CFFB0` 重新消费这个模型，原 UI 自己重画面板、计算行几何、绘字；`D0650` 重画真实当前选择；`D0570` 仍从同一原生记录做鼠标命中。无需以每页调用地址来选择重画片段。

实现多实例时必须区分活动输入模型与保存在原生背景中的父菜单模型；原游戏直接访问这两个全局块。不能只把共享全局地址存在旧窗口中，随后被下一次 `CF790` 清空。也不能把所有菜单头字段当成只读文本：原生输入正在维护其中真实选择、滚动等状态，重画时不得恢复过期输入值。以上是对使用已证实原生模型的实现要求，不证明整套多实例适配已经完成。

## 原生共同组件 ABI

栈参数均从原函数入口 `[ESP+4]` 起列出；以下函数由原调用者清理栈，不可直接用 MSVC `__fastcall` 声明让被调用者清栈。现有 `native_paragraph.cpp` 已示范以汇编桥保留原约定。

| 原生函数 | 输入及已有所有权 | 完整语义/适用边界 |
| --- | --- | --- |
| `CF790` | `ECX=color`、`EDX=title`；栈 `x,y,w,h,kind`，调用者清 `14h` | 初始化全局菜单模型、复制原标题、清100条记录并保存矩形/类型。`CF7F0..CF988` 明确为新模型生命周期；不能在语言变化时重调而清除真实选择/输入状态。 |
| `CF990` | `ECX=action`、`EDX=label`；无栈参 | 原英文行/动作加入原菜单模型；应在原生构建时建立语义身份，不修改动作值。 |
| `CFFB0` | 无参数；读取原菜单模型和主 surface `61BBB10` | 完整菜单组件绘图入口。原 `D02AA` 循环以 `E8h` stride 遍历模型；不是任意父页面重建入口。 |
| `D0650` | `ECX=selection`、`EDX=mode`；无栈参 | 使用模型的真实行矩形画选择底/边框；没有重新读取标签或构建文字。 |
| `116270` | `ECX=x`、`EDX=y`；栈 `w,h,title,flags,color`，调用者清 `14h` | 完整软件面板构建。背景图集来自 `A1C2028`；标题先复制到自己的原局部。函数自身不分配持久 panel 对象。 |
| `115E70` | `ECX=x`、`EDX=y`；栈 `w,h,title,flags`，调用者清 `10h` | 另一公共完整面板/标题接口，进入 `1157B0` 等原布局路径。不能把不同 flags 模式都当不透明背景。 |
| `114680` | `ECX=x`、`EDX=y`；栈 `label`，调用者清 `4` | 完整按钮：原图集左帽、重复tile、右帽与标记文字；可以作为有完整来源和背景的语义组件。它本身不返回持久按钮对象。 |
| `162300` | `ECX=reset`、`EDX=text`；无栈参 | 完整原段落源追加/分词。非零 reset 先调用 `1620C0`，原词槽 stride `82h`；不是字形输出。应在翻译前绑定原始文本语义。 |
| `1620C0` | 无参数 | 清全局词槽首字节、清计数 `A225314` 及原段落缓存 `61BB650`。这是原段落 builder 生命周期；单个共享全局词表不能作为所有已画段落的持久模型。 |
| `10EB40` | `ECX=x`、`EDX=y`；栈 `width,height,color,outline`，调用者清 `10h` | 原生完整段落布局/绘图，消费上述词表；原换行、行距、光标和标记归原代码。其局部模型在返回后消失。 |
| `10E5A0` | `ECX=x`、`EDX=y`；栈 `text,color,outline`，调用者清 `Ch` | 原整串软件文字消费。它只拥有本次局部串和原光标；不能在这里把已经拆分的所有text调用登记成“组件树”。 |
| `10E260` | `ECX=renderer`、`EDX=x`；栈 `y,text,color,outline`，调用者清 `10h` | 原整串renderer文字消费；当前真实target由原renderer控制。完整语义仍应来自之前已接入的构建边界。 |

## 真正的原生缓存所有权锚点

这些边界可以负责扩展对象的保存/恢复/替换/销毁，但其现有内容只有像素；不能从它们反推出未捕获的原文或父子关系。

| 原生接口/owner | 精确 ABI/动作 | 能绑定的生命周期 |
| --- | --- | --- |
| `10C540` 按名保存 | `ECX=name`、`EDX=原rect*`；无栈参。`10C661` 写实际surface到 `A1C1CC4[EBX]`，`10C66E` 复制主面，`10C67A` 保存原rect指针到 `A1C1CA0[EBX]` | 四个原生按名背景槽；同名替换先 `10C5AF→10C4C0`。可在真正成功保存时绑定当前原生组件owner身份；不能把name解释成页面类型。 |
| `10C690` 按名恢复 | `ECX=name`；无栈参。`10C70B` 用原rect从槽surface恢复到 `61BBB10` | 让扩展原生组件owner随同一个槽恢复。原局部rect指针的使用和生命由原代码保持；不能另造固定矩形。 |
| `10C4C0` 按名释放 | `ECX=name`；无栈参。`10C514..10C51A` 清该槽100字节名称，`10C51F..10C526` 释放原surface | 扩展组件与该真实槽一同退役；不保留可延迟重放的悬空组件。 |
| `10DA10` 一级背景保存 | 无参；`10DA3C` 将主面复制到 `A1C2014`，原矩形来自 `1DDAB0` | 保存当前原生父窗口owner。注意主菜单许多路径直接 `UpperBlit` 到相同 `A1C2014`，不经过 `10DA10`。只Hook此函数不能完整覆盖所有保存。 |
| `10DA60`、`10DAD0` 一级背景恢复 | 无参；`10DA71/10DAF1` 复制 `A1C2014` 到主面；后者维护原 `61BBA5C`/显示状态 | 恢复原父owner并让原生呈现生命周期继续。不能在通用SDL拷贝处猜测任意资源都是父窗口。 |
| `10D340` 二级保存 | 无参；仅原 `61BBAFC==0` 时在 `10D375` 复制主面→`A1BBD24`，随后置标记1 | 二级owner与一级必须分开，不能混用。已有保存时函数不会重建缓存或改变owner。 |
| `10D3A0/10D420` 二级恢复 | 无参；`10D3B1/10D441` `A1BBD24`→主面；两者返回前都清 `61BBAFC`，后者同时维护原显示/overlay状态 | 二级对象恢复；不存在任意深度栈的原生证据。 |
| `D1189` 菜单工作面保存 | 原 `SDL_UpperBlit(61BBB10,&rect,A1C1CE0,&rect)`，rect来自 `1DDAB0` | 一个已布局完整菜单和其原背景的输入生命周期。不能把进入 `D1120` 等同于全页语义已捕获。 |
| `10DBB0` 菜单工作面区域恢复 | `ECX=x`、`EDX=y`；栈 `w,h`，调用者清 `8`；`10DBE3` 按原矩形从 `A1C1CE0` 恢复 | 属于选择/控件恢复。语义owner由菜单工作面本身持有，不依赖Mod文字包围盒相交判断。 |
| `10B9F0` 清主面 | 已确认 `10BA17` FillRect 原主面逻辑矩形 | 可以清理相应原生root的组件生命；仅此一个完整清屏点不能覆盖原生所有局部替换。 |

现有 `native_targets.cpp` 中 Create/Convert/Free、renderer Create/Destroy、texture Create/Destroy 的身份/密度登记只证明实际资源生命周期已接入，不证明有可供重建的语义。这套资源登记可以为新的原生组件owner提供身份锚点，但不能把位置/文字历史塞进密度记录后称为所有权扩展。

## 绑定完整语义的可实施原则

原生扩展 `Menu` 的来源是上面游戏自己定义的菜单模型；`Paragraph` 的来源是原 `162300(reset/append)` 构建过程及之后唯一完整段落调用；`Button` 的来源是原 `114680` 完整控件调用；面板的来源是 `116270/115E70` 的完整原生构建接口。它们应在原构建过程产生自己的组件对象，保留原始英文模型及该对象的原输入关系，按真实原生owner分配/销毁。语言代数变化只令这些原生对象失效，然后由同一原生组件接口重新布局并立即画入该owner；不通过Present执行，也不重新运行游戏业务函数。

上述是可以实现的公共组件扩展方向，不是现有源码的功能说明。当前仍需实现或确认：

1. 面板、按钮及段落在原版中是即时绘制函数，没有持久对象返回；必须实际扩展这些原生接口的组件所有权。仅把 `NativeEvent` 的x/y/text/color参数放入一个 `vector<Draw>` 再遍历，仍是绘制贡献记录。
2. 必须在真实语义层确认父组件归属。不能以“最近一次面板”“坐标落入这个矩形”或某个默认页面类型来猜父子关系。当前已证实的强owner是实际目标surface/texture、完整菜单模型以及明确保存/恢复的原生缓存槽。
3. 背景、控件、段落之间的覆盖/替换必须沿原组件自身的清理与缓存构建边界。没有确认语义清理时，不能扫描/比较像素推断旧字，也不能只把较短新文字画到旧字上。
4. Hook共同组件可统一今后的构建；过去已经显示且没有建立语义对象的像素，不能在不重新进入确认构建边界的情况下恢复原文。热发布 Applied 本身不能补发过去的语义构建。
5. 原 `10B3C0` 的128个图片槽与caption属于另一种已存在的原生对象；其范围和限制见 `20261019-global-language-cache-audit.md`，不能把所有软件文字塞入这些图片槽。

本记录没有引入页面到重绘地址的映射，也没有宣称所有原生文字组件生命周期已经确认。它补充了可以实际扩展的原生语义模型和确定的缓存owner锚点，保留尚未确认的接口为后续静态工作。

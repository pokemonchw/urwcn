调用与事务
==========
- native_bridge.h 定义 Phase Before/After、借用 Frame 指针、稳定 token
  与 DispatchResult.call_original。adapter Before 返回后先释放租约，
  驻留桥才执行登记的原函数；返回后重新取得当前代 adapter 作 After。
- adapter 不再调用 native_call/original；原生阻塞时只有游戏和驻留
  调用帧。native_* 按值保存作用域、选项、进度参数及 token 续接状态，
  不保存旧业务模块函数指针、局部栈地址或旧 SDL resource_id。
- control_bridge.cpp 统一包装 SDL 事件、等待、延迟与呈现。Wait 用
  内部 16ms 超时服务控制请求，超时不返回游戏；只返回真实事件或原
  SDL 错误。不伪造按键、不跳出窗口、不改菜单 return_address。
- Host 在无业务租约时处理事务，PREPARE 先保存状态，再失效和退役。
  ReadyToPublish 到 COMMIT 期间原线程留在驻留服务循环，原生等待和
  续接状态不前进；收到提交后激活当前代并恢复原调用。
- Shift+F5 直接原位 Reload。Footer/Poll 标记与菜单退出分支已移除。
  adapter_op::rebuild 使用已保存的当前显示请求；没有活动请求时成功
  返回，不凭空创建主菜单。显示排版/叠字的其他审查项仍待整改。

协议与迁移
==========
HostApi 内存布局和 Host ABI 仍为 3。adapter 服务版本、状态模式为
2/2；旧桥只接受 1/1，新旧调度语义不能混用。新版驻留桥严格核对该
版本，其余五模块仍为 1/1。

本次迁移前进程中已装载的旧 uwcn_loader.dll 没有升级自身的接口。磁盘上的
新版 loader 不会替换旧进程正在执行的驻留代码，单独热更新新版 adapter
也无法补上旧桥缺失的协议。这是本次真实通用桥迁移的实际限制，不是
“以后只能回主菜单重载”的规则。不得伪称当前旧进程已取得新版能力。

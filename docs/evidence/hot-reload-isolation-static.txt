原耦合原因
- 根 CMake 将 src/loader 下所有 cpp 链入驻留 DLL。
- native_hooks/native_setup/native_intro/native_credits/native_ancestors 包含
  界面作用域、字段读取、英文抑制、几何与固定补丁集合，新增汉化因此改驻留。
- host.cpp 直接依赖 FieldId、请求结构和 DisplayPlan，并持有显示业务流水线。

本轮源码结构
- loader 明确只编入 host.cpp 与 hook_host.cpp。
- native_* 全部迁至 src/modules/adapter；原 host 的显示业务迁至 display.cpp。
- adapter 为第六个普通业务 DLL，模块 ID 6，掩码 32，全图业务掩码 63。
- ABI 3 增加通用 begin_display/display_enabled/image_base/replace_hooks/
  native_call 服务。loader 不包含 main_menu_fields.h 或 display_plan.h。
- render_control.h 仅声明通用绘制事务操作编号，不引入界面字段或显示记录。
- 包管理仅提供 metadata/package-identity 原字节；汉化版本的 SHA256、base36
  和字母数字格式算法归属可热重载 main_menu。loader 不决定中文内容或字号。

驻留桥生命周期
- adapter 提交无函数指针的 Patch/ByteCheck 数组；loader 复制其纯值。
- 驻留生成 push slot / jmp entry 的固定 x86 thunk，槽号与代码进程期不释放。
- CALL rel32、CALL [IAT]、CALL ESI/EDI 均按原字节描述原调用。
- 覆盖 CALL+ADD ESP,4 的位置使用独立 ret 4 入口；六字节 CALL 保留原清栈。
- present 由 adapter 决定是否中文合成，原 SDL 调用通过 native_call 执行一次，
  保留原函数 EAX/ECX/EDX/flags 写回。
- adapter dispatch 的租约覆盖原生调用及其返回，允许跨窗口等待。
- Footer 边界在进入 adapter 前检查全部租约；交接后重新读取当前稳定槽。
- 关闭 gate 与再次核对租约在同一同步协议下完成。
- adapter 退役前作废显示计划、恢复几何；驻留保有纯值原函数路由和控制 Hook。
- adapter 缺席时 Footer/Tick 继续处理恢复请求，原生调用走原文路径。
- 新代激活时整体核对原字节和控制描述、恢复旧业务跨度并登记新集合。
- 只改其他五模块或词库不会重新安装补丁。

交接及发布边界

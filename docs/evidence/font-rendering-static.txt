Mapping interpretation
-----------------------
Both frame copies pass NULL source and destination rectangles. In SDL 2.30.0,
SDL_RenderCopyF takes the whole texture and RenderGetViewportSize when these
rectangles are NULL. RenderGetViewportSize divides stored physical viewport
width/height by the current renderer scale, and the copy applies that scale.
The resulting frame destination spans the physical viewport. This SDL source
contract, together with the native arguments above, supports mapping the
800x600 main-menu canvas to the actual content viewport. The viewport must be
read from SDL rather than inferred from desktop aspect ratio or window size.

Source:
https://github.com/libsdl-org/SDL/blob/release-2.30.0/src/render/SDL_render.c#L2290
https://github.com/libsdl-org/SDL/blob/release-2.30.0/src/render/SDL_render.c#L3149

This describes pixels inside the SDL output buffer, not physical display pixels
after Windows composition. It does not establish process DPI awareness.

# 原生消息文字工作区容量

仅静态读取 3.89 PE；地址为 VA。原始反汇编位于 `build/windows-sync-pe.asm`。

原 `F6510` 的 `65A84B8[400]`、当前词 `65A96A0[400]`、栈上 `ESP+B0[400]` 均不能以英文容量直接容纳任意长度的中文编码结果。此前 `windows_messages.inc` 借入中文时的 `strcpy` 缺少容量依据，且原生追加历史同样存在这个问题。本次源码移除该写入，没有添加截断或未命中透传。

`Display` 为这一次真实 F6510 调用保有三段文字工作存储，每段容量均为实际 `encoded.size()`，包括 NUL。第一段是中文源，第二段由原生逐字复制、词边界与 clear 指令使用，第三段由原生逐词历史追加使用。它们没有坐标、布局、像素或绘制贡献记录。所有字形仍在原生绘制调用立即提交。

| 原指令 | 接入的实际文本操作 |
| --- | --- |
| F6A45 | ECX 正文起始指针，后续原 strlen 循环继续执行 |
| F6A6D / F6A76 | 当前和前一个字节是否空格的原生双空格分支 |
| F6A80 | 原生 CL 当前字节读取 |
| F6CCE | 后续循环长度扫描的正文指针 |
| F6BF7 | 原生当前词追加目标 |
| F6C21 / F6CEC | 原生当前词长度扫描 |
| F6C5C / F6D1E | 原生历史追加源 |
| F6C6A / F6D2C | 原生历史追加目标 |
| F6CA1 / F6D64 | 原绘制调用的文字参数，保持原坐标及样式参数 |
| F6CA6 / F6D69 | 原生游标推进前长度扫描 |
| F6CB8..F6CC9 | 与原 width 扩展共同清空实际当前词 |

原 token 扩展在 F6BE0 一次复制完整的两字节传输字符，并推进原 EBX。原生 F6C14 对该 token 采用其已有词边界分支。正文只消费一次；颜色与 @ 字节被原分支抑制，双空格分支只会减少字节。当前词是已消费正文的一个区间；历史区按实际词依次追加，不新增分隔符。因此两者含 NUL 的最大长度均不超过分配的源编码容量。移除声音字段的 memmove 同样只缩短第一段。

`65A84B8` 未被中文覆盖，F6DE4 / F6E09 的感叹号颜色判定及后续声音仍消费原英文。日志调用沿用原英文正文的控制符处理，未将第三段中文历史内容传入文件。中文显示当前词按 F6510 的真实 EBP 身份查找工作记录，不能由外层调用的全局 scope 替代。

分页时原 F6510 帧、EBX、词缓冲、输入状态继续存活，工作存储由该调用的 Active 生命周期持有；F6EBB 完成后释放。未新增重画业务或分页输入。

第二个 Display 字段现在表示容量，不能把旧版正在分页的 borrowed=1 记录解释为新格式；必须按实际已发布版本确定迁移边界，不宣称已实现这种转换。下述 HDA4 是初次分析时的正式版本记录；后续发布及当前版本以 `20261020-shared-message-delivery.md` 为准，不能把历史快照当作当前发布状态。

读取当前 `package/release.json` 得到 Adapter 构建批次 `7c37c48420db4d878748c87f507a26d3`。对应批次日志使用 `build/.source-snapshots/hud-culture-6c22637`，其 `module.cpp:1378` 保存 HDA4，且没有 `windows_messages` / `message_body` 接入。因此该正式版本没有本次新增的消息工作记录；这项静态事实不等同于已经完成整体热发布。

另发现并修正了中间版本状态路径：`modules/adapter/module.cpp` 的 `restore_state` 原先把 HDA6 和 HDA7 都传给新的 `restore_windows_message_state`，而 HDA6 源码快照曾保存已译字符串，当前读取器消费 `Text` 图，会错误解释中间版本消息数据。现已从原有支持版本集合中移除未发布的 HDA6，消息图只按 HDA7 读取；没有默默丢弃旧数据或声称实现了迁移。初次分析时的正式 HDA4 不经过消息读取分支。

## 实际绘制与已禁止跟踪的区别

现行 `AGENTS.md` 禁止在通用 SDL 调用或原生逐像素写入处扫描、比较、记录游戏图像，以及保存像素、UTF-8、位置、裁剪、样式的贡献序列供以后重放。本轮接入的坐标扩展只执行原生当次绘制：接收已确认的原生操作及坐标，将结果立即写进该原生 owner 管理的实际高清资源。它不建立影子图像，不保存 UI 位置或绘制历史，不在上传、RenderCopy 或 Present 时重新生成旧文字。

原游戏填色、渐变等操作本来需要读取或比较目标颜色；保留这些原有算法语义，不等于允许 Mod 增加一套用于追踪文字覆盖的读回、比较和记录。字体自身缓存只可保留字体度量或相对字形原点的光栅，不可附带原生 UI 位置和页面记录。

`native_raster.cpp` 和 `native_raster_patches.cpp` 已接入整线、原生整字、单点及下列七个内联读写边界；内联整数辅助函数不经 Host 调度、FXSAVE、日志或事件记录。它们保留原指令寄存器、标志和栈语义，由 adapter 在卸载前撤除直接分支。SDL IAT 则发布进程寿命的固定 `E9` 入口，跨代只重绑定目标，详见 [稳定入口记录](20261019-native-target-stable-gateways.md)。二者的寿命不同，不能把业务 DLL 中的整数辅助函数称为永久驻留代码。

一条原生逻辑像素写入现在立即填入 `[edge(x), edge(x+1)) × [edge(y), edge(y+1))`，边界按整数比例就近取整；没有仅写乘密度后的一个物理点。读色使用同一逻辑格的精确中心 `floor((2*x+1)*physical/(2*logical))`，保持已有写后读关系；它不声称与 SDL 反向 16.16 缩放逐位相同。推导及源码范围见 [整数采样记录](20261019-native-raster-sampling-static.txt)，该记录中的算式不是已运行的测试。

## SDL 矩形、裁剪与上传边界

已确认导入：UpperBlitScaled IAT `18C17C`，FillRect `18C1E8`，UpperBlit `18C204`，UpdateTexture `18C21C`，RenderCopy `18C228`。当前 EXE 导入表及 SDL 符号字符串中没有 SetClipRect/GetClipRect；本轮未确认游戏调用这两个 API，不应新增一个臆测的“原生 SetClipRect hook”。SDL 软件面的 clip 字段仍由实际资源的创建及原生 SDL 操作管理。

- 高清背景到高清主面：源、目标矩形按各自真实资源密度转换。两面尺寸一致不代表可以略去原来的局部恢复区域。
- 原图片/图集到高清主面：保留源图片像素坐标，只转换目标逻辑边界；原普通 blit 的目标宽高并不提供缩放，必须在已确认图片调用边界接入实际缩放操作。
- 原生持有的 rect 仍是逻辑 rect。临时 SDL 物理参数不能反向覆盖它；源/目标指针别名、目标 rect 返回值及 clipping 的既有调用语义也要保持。
- FillRect 的 NULL rect 是当前实际面的 clip rect；原生新建面的默认 clip 覆盖全幅。显式原逻辑 rect 才需要边界转换。不能增加扫描旧内容、比较同色像素或更新贡献记录。
- `10AF90` 的 `10AFB6` 直接读取主面的实际 pitch/pixels，NULL rect 上传；`10B00C` 完整 RenderCopy。在主面与纹理实际尺寸匹配时，这条原生链可继续管理最终提交。
- `10B770` 中 `10B929` 同样上传实际 pitch，但 `10B953` 的纹理源裁剪仍由逻辑矩形形成，须转换源裁剪；该函数已有 renderer viewport / 目标坐标转换，不能再把目标乘一次密度。
- 淡变上传 `10D73C/10D84C` 也读取主面实际 pitch/pixels。其临时面生命周期由原生 `10D5B0` 持有。

## 已接入的迁移边界与仍然保留的限制

1. **窗口 resize 与密度变化。** `D1BC0` 事件路径的 `D1E99` 对 SDL_WINDOWEVENT 4/5/6/8/9 调用 `10ADB0`；该函数仍只重建 `61BBD14/61BBD04` 两张1800×1800 target texture。Adapter 新增 hook id 60，在该调用 After 执行 `invalidate()`；只有已确认的主菜单 `menu_input` 活动范围才执行资源迁移与原生重绘。随后原生平衡片段 `125BA3..125BE1` 重画页脚、面板、版本及菜单，再按 `D1189` 的原生逻辑矩形更新 `A1C1CE0`，用 `D0650` 保留当前选择，最后由 `10B720` 呈现。`D1DCA` 的 SetWindowSize 条件及其他窗口行为保持原生；不把这个接入写成所有窗口均可随时迁移。
2. **运行中迁移旧原生栈引用。** 迁移入口限定于 `125AF5/125BA3` 页脚构建 Before，以及上述已核主菜单输入重绘链。窄审查中，`125A90/D1120` 的直接帧未保存待迁移 surface/texture/pixels：`D1189` 保存后 `D118F` 清栈，`D1225 → 10AF90` 上传完成后 `D1298` 才 Present；`D1E99` 返回后的已核事件帧持有事件、键值、矩形和函数指针。外层 `125B79` 在 ESI 缓存 UpperBlit 的问题已由稳定 IAT 槽及旧驻留别名重绑定接入处理。反例仍保留：`10D5B8` 的 ESI 在 `10D77C/10D88C` Present 后继续持有旧主面，故任意 Present 或仅 `active_calls == 0` 均不能作为释放旧面的充分依据；本文件不将已核路径外推到所有下降分支。
3. **冷启动与实际尺寸。** `11768A/11774B` 创建 renderer 并保存 `A2110CC`，可选逻辑分辨率设置在 `11776D`，早于上传纹理 `11796D` 和主面 `1179B9` 的创建。SDL 创建 renderer 时已有默认 viewport；`output_scale()` 临时将 scale 设为1，取得窗口目标的物理 viewport，再恢复原状态。`117A48 → 10C110` 完成软件缓存创建，早于 `125AF5`；该构建边界会按当时输出密度同步现有 owner。主面实际 w/h 的已确认直接消费者是淡变临时面创建，未发现把它们重新用于逻辑布局的确定冲突；这不是所有间接消费者穷尽的证明。
4. **原生资源与访问范围。** 命名槽的799边界、普通图集像素域、BMP 导出工作面及淡变实际尺寸已经分别接入。现有接入覆盖本文确认的写读点、原生创建和 SDL 复制链；不声称所有 surface 别名、其他线程引用或未解析路径都已覆盖，也不把其他窗口的汉化算作本轮完成。
5. **即时字形与原生度量。** Adapter 已将主菜单 index 0..7、版本和页脚的已确认完整文本调用接到 Render。两字节 token 仅用于原生文本传输，实际逻辑宽度来自完整 UTF-8 字符串度量，并回到原生光标、版本居中及段落宽度入口。`immediate_text.cpp` 按实际主面宽高与800×600逻辑域生成字形，立即通过原 SDL 混合到该面；原生描边、前景颜色和调用顺序保留。字形缓存不持有 UI 位置或页面重放序列。

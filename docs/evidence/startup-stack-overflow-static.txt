静态原因
========
旧 native_cache::apply 在处理每个内容节点前递归 previous。原生缓存中大量
点写被逐点追加成历史节点，在后续文字提交的 write_surface 中递归物化，
超过线程栈容量。扩大线程栈或只跳过绘制都没有消除该实现问题。
同一内容结构的 clipped、erase_covered、erase_same_text、collect 及默认
shared_ptr 析构也沿前史递归。当时处理了深链栈依赖，但未消除这套
全局内容跟踪与重放方案本身；不能把当时的局部修复当作当前设计要求。

只读反汇编确认，外层 urw+E3020 原生离屏构建先画标题，再经 109260 等
绘制图形，最后在 E39E4 调用 10E260 画文字。109260 内有多处经 IAT
18C1C0 调 SDL_RenderDrawPoint 的循环（1095CB、109632 等）。每像素新增
节点和遍历旧前史既增长调用深度，也增加同步启动工作量。
转储没有提供完整节点堆供逐项分类，未声称已从堆中统计每种节点数。

当时实施、现已撤销的局部修改
============================
当时仅修改 src/modules/render/native_cache.cpp，下面记录历史事实，
不要求保留这些节点、工作栈或迁移结构：
- apply 使用显式工作栈，保持 previous 先画、当前操作后画；嵌套 Blit 源
  使用独立堆 Canvas，保留源裁剪、混合次序与实际字形密度。
- clipped 与状态 collect 使用显式后序，历史清理按 previous 自底向上
  重建。序列化仍保证子节点 ID 先于引用它的节点。
- 全部 Node 使用无分配的迭代释放队列；最后引用释放时先移出两条子引用，
  再逐项释放，避免绘制修复后又在缓存销毁时栈溢出。
- 连续替换式 Point 合并到 Pixels 尾层，保存颜色与独立有效位。仅合并
  无 key/mod 的 blend0，或颜色 alpha 与 Paint.alpha 均为255的 blend1。
  半透明混合继续保留原操作语义，不用最后一次颜色替代累积结果。
- 尾层只在唯一持有时原地更新；源纹理、背景副本等共享时仅复制该尾层。
  透明原始像素写入仍有效；未写过的洞保留前史。映射继续采用原 Point 的
  output.rect 整数 round 边界，保留非整数倍率下的覆盖语义。
- 文本节点与背景前史保持独立，未把文字烘焙成低清位图；仍在最终输出
  密度重新光栅化。没有深度阈值、丢弃内容或另建 Present 叠字方案。
- NodeRecord 仍为纯值内容；Pixels 使用新增 kind 8 和已有 pixels 字段的
  color/valid 对，恢复时校验完整成对尺寸。旧 kind1..7 内容仍可恢复。
  Host ABI、loader、启动器、adapter 均未改。

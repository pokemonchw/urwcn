# 姓名输入与错误页脚的原生语言重建

目标为 Windows x86《不真实的世界》3.89.1，原 PE SHA-256 `c6ed73642c1b1cb1f86b818c7586224398c2f0554f6114ced31bc40ff071806d`。所有地址为 RVA。只读原 PE 指令及源码；没有游戏运行、输入模拟、测试、测试用例或断言。

## 共同协议

语言选择仍只产生共同原生构建请求。正在编辑姓名时，实际 getst (`10F5B0`) 于 `10F71E` 收到原生非按键 `-2`；真实 `[EBP+4]==base+119B0` 确认它属于 Choose_Name，没有用全局当前页面猜测帧。原调用指令 `6A 64 8B D8 8D 45 90` 由完整指令组成，普通输入仍执行原压栈、返回值和局部缓冲构建。

重建先调用已确认的父窗口完整原生图片及标题片段，再运行文化和性别的原生完成态。随后建立新的 `11870` 纯显示帧：

- `1189C→118B3` 跳过共享初始输入缓冲清零。新函数自己的错误局部已由原 `11886..11899` 初始化；当前原生错误模式为2时，提供该已接受错误资源的原英文来源，让原 parser、帮助后缀和 F210 完整构建继续执行。
- 原 `119AB` 输入 CALL 只在这个新纯构建帧中跳过，Before 和 After 均不进入 native_name_input 的 IME 生命周期；原先真正的 getst、输入缓冲 `A49B9A8`、容量和已提交文本状态均保持。
- `119B0→11C5D` 跳过姓名复制、验证、随机取名、目录查询/创建及完成灰化；该尾部正确弹出三寄存器、核对原栈 cookie 并退出新帧。
- 回到真实旧 getst 帧，ESI、EDI、EBX 分别借用其原 `[EBP-A4h]` 输入原点、`[EBP-B8h]` 行位置及 `[EBP-ACh]` 颜色，再续接 `10F6A0`。输入文字、下划线、光标、上传、呈现和下一次等待全部由这个原帧管理。没有保存帧指针、布局或文本绘制贡献。

## 完整错误组件的真实输入

旧版本确实没有保留 F210 错误底色所需的输入，但这不妨碍在该原生组件自己的正常构建边界补齐输入生命周期：

- `11904→F210` Before 记录 Choose_Name 本次真实 ECX 模式（普通0或错误2）。
- `F24A` 位于原 rand 循环已经完成、`CMP [EBP-4],2` 与 `LEA EAX,[EDX+0Fh]` 之前。只有该函数真实返回 `11909` 时，接受它当次真实 EDX 余数。它是本次 UI 颜色构建输入，既不是游戏随机状态，也不是像素或 UI 几何。
- 切换构建时，`F21D` 写入同一个原生模式局部，借用已接受的 EDX 输入，转 `F24A`。原 `F24A..F289` 或 `F293..F2AD` 自行映射颜色并构建完整底板，再执行原 `F2E5` 段落。不会重跑 rand，也没有另设颜色、扫描像素或改变原生错误样式。

`WindowsProfileErrorSource` 仍先保存既有的错误类型与原文 RVA，后面附加两个 u32：footer_mode、footer_tint。原 HDA7 UI 分节本来已有字节长度；该节由8字节扩为16字节，不改 Host ABI、Active 或其它分节布局。16字节版本保存并恢复真实接受输入，之后的每次正常构建都更新它们。

早期草稿曾根据用户“没有停在姓名错误页”讨论8字节旧节的局部迁移；该方案已退出最终实现。用户要求完整处理所有界面，后续普查确认旧Command、关键词分支及SECOND来源也存在不可恢复历史。本轮最终采用HDA8完整19节状态，只恢复自身的16字节错误来源，不接受HDA7旧状态、不猜模式或色调；不把当前停留页面当作兼容迁移前提。详见 [最终交付记录](20261110-language-switch-completion.md)。

源码位置：`modules/adapter/native_full_language.inc` 的 `name_input_result`、`name_initial`、`name_result`、`name_footer_tint` 与 `creation_footer_rng`；分节数据在 `windows_profile_extras.inc::WindowsProfileErrorSource`、`module.cpp::restore_native_ui_state`。编译及正式发布将与共同构建/缓存协议的其余修改统一记录，不以这份静态记录声称产物已经更新。
# 同轮静态交叉审查补充

`10F71E` 的 `-2` 同时可能来自语言唤醒和真正的 `SDL_TEXTINPUT` 提交。重建分支明确要求原输入状态 `committed==0`，真实提交继续原 `10F77F` 编辑分派并追加到原缓冲，不以语言请求吞掉首个字符。

英文 Unicode 范围按真实完整文本 CALL 建立；原 HUD 姓名 `FA493` 的独立宽度消费在原输入上建立同一 Unicode 度量范围。祖先 `DD400` 的 `DD7AF` 姓名和 `DD82B` 原死亡描述两个完整 `10E5A0` CALL 补入通用范围，避免只修活动姓名输入而遗漏保存后的中文姓名。属性姓名、两类原生标题、菜单选框与注释、三个输入擦除宽度均沿各自已经确认的完整调用/度量范围。

同步 `UnicodeMeasure` 使用逐次独立的保留域 token；嵌套度量析构只移除自己的范围，不提前移除外层。

# FIRST 原生缓存语言生命周期

静态来源：原始 Windows 3.89.1 `urw.exe`，映像基址 `00400000`，以及 `build/analysis/windows-3891-native-full.asm`。本文地址均为 RVA。本项未启动游戏、未模拟输入、未编写或运行测试、未编译。

## 单一原生 revision 提交

每次 restore 按同一 FIRST slot 的 `cache_needs_language` 判断是否要构造。需要构造时暂存并设置原 `61BBA5C`，从已还原的真实父像素进入完整 HUD 或主菜单构造，然后调用原 `10DA10`。该函数使用原 whole-screen rectangle、原主 surface 与 `A1C2014` 完成 SDL copy，`10DA42` 的既有 native owner callback 才提交当前 language revision。随后还原原 flip 值，继续原 CMP 和原呈现生命周期。

主菜单使用既有 `native_full_language::parent_main()`，它本身在完整构造后调用同一个原 `10DA10`，因此不另存第二次。新的 restore 不以 pending 位代替 cache revision；先前子窗口已经消费 pending 时，旧 FIRST 仍会在真实恢复边界消费自身 revision。

## F5A30 暂停父的真实构造

`F5A30` 仅有原 caller `6BA0F`。`6B760` 涉及收集/写文件/处理业务，不能重新执行整个函数。原调用路径在 `6BA00` 装入 `ECX=100`，`6BA05` 调 `64730`，随后才进入 `F5A30`。命名 `59AD18` 的实际字符串为 `statscreen`，不是交易页。

`pause_parent()` 首先用完整 HUD 恢复其消息所有者，再运行真实 `64730(100)` 的原框、标题、记录循环、语法格式化、行控件和着色。`647D0..64AF2` 是每条记录的依赖计算与首次数值初始化，会写实际业务表；在这个同步构造阶段跳到 `64AF3`，令 EDX 从原 `EBX + 1D30CFC` 接受值读取。EBX 是原循环的 `244h` 记录步幅，不保存文本行槽或坐标。`64AF3` 即原 `MOV EAX,EDX` 后的完整显示路径，原循环仍负责所有行控件。

`65034` 判定终端输入，`100` 在 `65042` 选择原 `59A13C` 消息，再于 `6522E` 调 `F6510`。完整 HUD 已通过 canonical message owner 消费该真实已接受消息；本次纯统计构造只跳过这次新 append，避免把终端业务消息重复提交。普通原生 `64730` 调用不使用这些门控，仍按其原业务语义执行。

当前活跃暂停窗口的语言刷新与 FIRST 退出恢复共用这一 `pause_parent()`；前景按钮仍由原 `F5A30` 负责，原已暂停的输入帧不重新执行。

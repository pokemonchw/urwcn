# Shift+F10 语言切换的原生重绘边界

日期：2026-10-19。对象为 UnReal World 3.89 / Steam Build 25939378，原 EXE SHA-256 为 `e0b15bbbe16ffcd95d4ab61f08fe95dea4b95ebe1b3de428dae1d9477a9710d9`。以下地址均为 RVA；引用反汇编以首选基址 `0x400000` 显示 VA。本记录只依据已保存的反编译、反汇编和源码，不表示已运行验收；没有启动游戏、注入、模拟操作、执行测试或创建测试与断言。

本记录区分“全局语言选择已经切换”和“原生 UI 已重新构建当前像素”。不得通过后者尚未发生，推导出保存整页文本、位置或绘制贡献并在 Present 重放的授权。

## 显示开关与基础服务

语言选择作用于已经确认的文本构建、格式化入口：选择中文显示文本或该调用的原文。原英文业务数据、菜单索引、设置值与动作保持原有语义。中文编码、完整串度量、字形绘制、原生目标尺寸扩展和调用作用域清理继续运行。

不能直接关闭 `src/loader/host.cpp` 的业务模块调用门，也不能因选择英文就停止全部 adapter dispatch。原生调用栈可能仍持有已构建的双字节编码显示副本；停止其解码、度量或绘制，会让它进入按字节消费的原路径。汉化署名等新增显示组件则随中文显示选择开关。

## 主菜单：已确认的同步重建

`125BE1 → D1120` 标记主菜单输入等待。原生绘制片段 `125BA3..125BE1` 依次调用页脚、面板、版本和菜单文字，栈内五次 PUSH 由 `ADD ESP,14h` 平衡，不读取外层 EBP，并在进入输入等待前结束。依据为 [原生片段反汇编](rebuild-native-call-disassembly.txt) 第 735–750 行及 [原生边界记录](rebuild-ui-boundaries.txt)“热应用时的原生重绘”。

重建后继续使用 `D1189` 对应的原生工作缓存复制：源 `61BBB10`、目标 `A1C1CE0`、原矩形 `1DDAB0`。`D0650([5F54AB0],0)` 保留当前选择，`10B720` 执行原生上传与呈现。此路径能替换当前主菜单的已绘文字，同时更新原生后续使用的缓存；它没有保存另一份页面布局，也没有重入 `D1120`。

当前 `redraw_menu()` 在主菜单输入作用域中执行，也在下述关于窗口的原生主菜单背景恢复后执行。不能在开场、启动失败等待或任意其它窗口里调用主菜单片段来充当全局清屏接口。`D1E99 → 10ADB0` 是窗口事件中的资源重建，单独发生也不等于所有文字被重新构建。

## 启动加载：下次对应原生构建生效

启动标题只有 `180894 → 10E5A0` 这次显示构建；随后原生面保存结果。已有证据没有给出“仍在启动时只重建这个标题且不执行其它启动业务”的完整接口。依据为 [启动标题记录](startup-loading-static.txt) 第 18–45 行。

进度函数 `123DF0` 每次先通过原生 `SDL_FillRect` 清理自己的进度矩形，再在 `123E6D → 10E5A0` 绘制当前行，最后仍会把原英文写入 `init_log.txt`。原生矩形来自 `1DD8A0`，本记录不授权把它复制成 Mod 行槽。依据为 [音频启动记录](startup-audio-static.txt) 第 130–173、224–269 行。

因此，后续新的原生进度调用可以使用新语言，并由原生已有清理和绘字流程更新该行；这不表示标题或其它旧像素也一并换语言。`B01B → D3C80`、`180946 → D3C80` 的失败等待仅呈现已有原生像素，不重新执行对应文本构建。不得为了切换语言重调完整 `123DF0`，因为它还截断原输入并写初始化日志。当前失败页即时文字重建接口仍待确认。

## 开场：持续帧没有完整文字清理接口

唯一直接入口为 `18097D → 1254C0`，返回 `180982`，精确字节为 `E8 3E 4B FA FF`。依据为 [开场记录](intro-static.txt) 第 20–34 行。当前源码已在该调用 Before 将全局语言保存为本次序列的 `intro_chinese`；它不保存文字、坐标、颜色或页面快照。

两句引言在 `1255EC`、`1256C2` 调用原生完整串绘制，分别进行 63 次灰度绘字。每帧在绘字后上传、呈现、延迟及检查输入，没有每帧恢复文字背后的背景。`intro-disassembly.txt` 第 280–321 行可见第一句循环从 `1255C1` 到 `125653` 直接回到颜色及文字调用。第二句同样保留第一句的已绘像素。

因此，在这些持续帧之间改变同一条引言的语言会把不同字宽的文字绘到已有像素上，无法由“下一次文字调用”证明旧字会被清除。不能将这种逐帧替换称为完整即时切换。两句后的 `1257B6 → 10D5B0` 淡出已有像素，`1257BB → 10B9F0` 清屏，`1257D7 → 1127C0` 构建后续背景，属于原生序列推进；不得为语言切换额外重播这些动画或业务流程。

诗文 `125370` 每行在 `125400..12541B` 从原英文表复制本行到 `[EBP-70]`，`125430` 构建显示副本并返回真实宽度，原生后续计算居中。`125445 → 125240` 的 63 次淡入与最终定色复用同一副本，文字调用为 `125285` 与 `12530E`。完成行留在原生主面，每行后的等待只检查输入和时间；完成整组后的 `125905 → D3C80` 也不会重新构建所有已显示行。依据为 [开场反汇编](intro-disassembly.txt) 第 8–94、135–202 行及 [开场诗实现记录](20261019-intro-poem-native.md)“原生颜色、等待和淡变”。

全局选择可以在开场期间更新，但当前完整开场序列继续使用进入时确定的语言；选择在后续原生页面或自然再次进入开场时生效。当前 `translate()` 按两句引言、十一句诗文的明确组件身份，以及版本调用的 `Scope::intro_version` 选择 `intro_chinese`，不依赖是否捕获到完整开场调用的 token。已确认的旧 HDA2 代始终使用中文，迁移其状态时 `intro_chinese` 初值保持 `true`，直到自然再次经过 `18097D` 才重新捕获全局选择；因此已经进入旧开场的序列也不会因本次显示开关改变语言。

这样保留原生灰度、定色、等待、跳过和缓存语义。仅保存本次序列的语言选择不构成整页中文字段快照。把开场每条旧文字立即替换且保持当前动画进度的原生重建接口尚未确认，本轮不得宣称已实现。

## 设置：保留原帧的完整重建 continuation

当前源码已包含 `setup_panel`、底部文字、退出控件和 `setup_text_calls`，并已接入独立 `native_language_redraw.h/.cpp`：adapter 初始化调用其 `initialize()`，注册三个 inline Hook，快捷键切换语言后调用 `request()`，并由 adapter dispatch 执行以下 continuation。两个控制标记已经加入 HDA3 状态交接。以上是源码接线事实，编译与正式发布仍须以对应交付回执为准。

`105700` 创建 setup 自己的 EBP 帧并保存 EBX/ESI/EDI，`105716` 是 prologue 完成后的原生绘图入口。`106B20 → D1120` 是本页输入等待；普通 `-1` 在 `10707F..107082` 只回到同一输入入口，不能仅返回 `-1` 就宣称设置页完成重建。依据为 [设置反汇编](setup-options-disassembly.txt) 第 153–265、1368–1381、1753–1773 行。

在 `D1120` 自身的 `D12B4` inline 边界，原字节为 `8B F8 8D 85 F8 FB FF FF`（`MOV EDI,EAX; LEA EAX,[EBP-408h]`），位于 `D12AF → D3BF0` 输入调用返回后。两个完整原指令均可原样重放。`D12AA` 实际为相对 CALL，不属于现有 inline replay 支持的指令，不能把它当作相同替代点。新的 [设置输入反汇编](20261019-language-setup-input-disassembly.txt) 保存了这两处及 `D19B3` 的原始指令。

`106B20` 保持没有 CALL Hook，使此时 `[EBP+4]` 确为原生返回地址 `image_base+106B25`。有 pending 语言请求、这次返回值为原生非按键唤醒 `-2` 且这一值匹配时，走 `D19B3` 原生退出 continuation，再在原 setup 帧中改走绘图 continuation；不保存或从外部重造 setup 栈：

1. 在 `106B25` 登记 inline 边界，原字节 `8B F0 83 FE 64` 为 `MOV ESI,EAX; CMP ESI,64h`。仅对应语言重建请求时，令 ESI 为当前原生选择 `[5F54AB0]`，从 `105716` 继续。这跳过选项动作分派，保留该函数原有 locals、cookie 和返回地址。
2. 原 `105716..1057E2` 绘图像、全页面板及标题，重新取得原生颜色并存入 `[EBP-84]`，执行原生上传。该块不读写配置，也不淡出音频。
3. 在 `1057E2` 登记 inline 边界，原字节 `C6 45 8A 00 33 F6` 为局部清零及 `XOR ESI,ESI`。仅本次重建时跳到 `10580D`，避开完整 `1057E2..10580C`：三项初始局部清零、选择清零、`1057F0 → 16D110` 配置读取和 `105804` 音频淡出。原初次进入保持这段原指令。重建保留本来已建立的局部选项编号，行为与设置原正文重绘相同。
4. `10580D..1058A5` 用原生文字流程重建底部帮助与安装路径，并由 `1058A0 → 10C540` 更新 `setupscr` 背景缓存；随后自然进入原 `1058B0` 的正文/控件重建，再到原 `106B20` 等待。

`10C540` 的同名缓存更新已补充只读反汇编：[设置缓存反汇编](20261019-language-setup-cache-disassembly.txt)。`10C570..10C597` 比较原生缓存名，匹配时 `10C5AD..10C5B4` 调用 `10C4C0`，先清原生名字槽并释放其旧 surface；`10C5C0..10C687` 在该原槽保存名字、创建/转换 surface、复制当前主面并保存原参数。因此同名 `setupscr` 的再次原生保存是替换，不应由 Mod 遍历或重放其像素、也无需新建平行缓存。

原生所有文字和布局仍在其自己的调用中重新生成。设置中的两个 inline 分流均发生在真实 setup 帧内；不能把 `105716..106B20` 交给现有 `HostApi::native_fragment`，因为该片段访问 setup EBP。也不能整次重调 `105700` 再人为退出，它会重放初始化配置和音频业务。当前普通输入消费路径沿 `D2083` 的原生非按键 `-2` 返回，使 `D3BF0` 返回后到达 `D12B4`，没有伪造菜单选择或执行原设置选项动作。

Helper 只保存 `pending` 和 `rebuilding` 两个整数标记。请求发生在其它页面时，未来首次自然进入设置的 `1057E2` 正常分支清除 pending，因为这一页已经按当前语言构建；已打开设置已经越过这个初始边界，pending 在 `D12B4` 被消费。三个 Hook ID 为 `0x5100..0x5102`，不保存 native frame 指针或 UI 内容。adapter 的 HDA3 后缀保存全局语言、`intro_chinese`、F10 消费状态及这两个重建标记，共五个 `u32`；HDA2 的原 Active 与原生资源格式保持原有含义。

# 开局介绍页黑块：运行中内存取证

日期：2026-10-19（Asia/Shanghai）。用户明确要求“追踪内存来确认”。目标 PID `121728`，实际 EXE 基址 `0x005B0000`，场景值为 `1`（村庄）。下文游戏地址均为 RVA。

## 结论与限度

截图黑矩形与当前原生地图视域 `{15,85,450,460}` 对应。当前原生呈现状态选择 `11016F → 10FC30 → 110260` 地图纹理复制分支，不选择 `110096` 的纯黑填色分支。结合介绍页等待栈与截图，黑块高度确定是地图合成层覆盖介绍页；这不等于已经证明汉化是触发原因。

本次没有记录过去的绘制调用，也没有读取 GPU 纹理像素，不能将当前标量快照当作逐调用历史；没有证据宣称纹理内容为何变黑已经解决。尚未建立“哪一次 Mod 操作改变原生地图缓存或合成条件”的因果链。不能仅凭存在汉化 Hook 或高清资源即归因汉化，也不能仅凭实际 RenderCopy 是原生函数就排除汉化。

## 与静态证据的交叉核对

- [原生呈现与合成反汇编](20261019-scenario-static-disassembly.txt) 的 `D3C90..D3CCD`、`110050..110260` 确定上述分支。
- 原生 `F5740` 从常量 `5DDAA0` 初始化地图矩形为 `{15,85,450,460}`，不是 Mod 新建的固定布局。
- 原生 `17E860 → 10D9A0` 和介绍页 `D3C80` 均会经过同一地图合成；`FB390/FB7D0` 不清这组地图状态。
- `4D8F4F1` 在原生加载链 `17C9F0` 中临时设1、`17CA9D` 清0；当前为0本身不是 Mod 破坏它的证据。
- 当前 Mod 源码未发现直接写上述视域、地图合成开关或三颜色字段。`native_targets::output_scale()` 与重绘接入是否曾间接影响缓存仍待确认。

## 操作边界及交付状态

使用 `OpenProcess(0x410)` / `ReadProcessMemory` 读取已确认标量、资源头、指令和线程栈。为获取主线程寄存器进行了短暂 SuspendThread / Wow64GetThreadContext，每次均在 finally 中 ResumeThread，原暂停计数为0。未设置断点、修改寄存器或目标内存、注入调用、模拟输入、启动或重启游戏，也未读取软件面或纹理像素。

本次仅新增取证文档和 JSON；辅助采集脚本保存在 `build/analysis/scenario-black-block-capture.ps1`，不是测试脚本或运行副本。没有修改产品源码，没有编译，没有正式发布。工作区其他聊天的既有及并行修改保持原样。

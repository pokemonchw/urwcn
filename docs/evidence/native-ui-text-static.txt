问题与本次范围
==============
上次交付只修正任意界面模块交接和发布脚本，仍保留了 Mod 独立显示计划。
About 打开后，原生保存的主菜单背景没有中文；原先 Present 叠字场景又已

本次实际删除这条实现链，处理当前全部已授权窗口的原生文字入口。

代码与职责
==========
- adapter 在原生整串文字、sprintf 结果、段落 append、控件参数及原生
  strlen 前提供编码文字，不修改游戏内部值、原选项值或业务动作。
- main_menu 现在一次只格式化一个原生字段；汉化版本仍由正式六模块及
  词库身份计算，不再生成 FieldSet 页面。
- semantic 只提供译文与数值格式，已移除颜色、描边、FontRole 布置。
- layout 只解码 UTF-8 供原生字体编码；没有窗口位置、行槽、按钮或命中区。
- render 为普通文字只生成 8x10 字形半格的 80 字节 0/1 font bitmap。
  adapter 在已确认原生 glyph 调用前暂借用原字体表条目，原函数绘制后
  恢复原 80 字节。真正绘制、颜色、脏矩形、surface、纹理目标、上传和
  缓存全部由原生 glyph 与其调用者执行。彩色 E000 标识是单字形扩展，
  在同一原生文字链同步落入当前目标，不建立页面或 Present 叠层。
- DisplayPlan、FieldSet、固定槽位、apply_geometry、selection 几何
  改写、mouse_index 和全部业务 Present 合成均已从维护代码删除。
  废弃 SDK 头先移入 回收/20261018-native-ui-source/sdk/。

编码与原生度量的静态依据
========================
已确认 10E5A0 只将 C4/E4/F6 改为 8E/84/94；10DDB0 按字节推进 8，
10BD90 按原 font8x10 表绘制。原字体表 RVA A1BBD28，每项 80 字节，
地址公式来自原 10BDCB..10BDD5；10BF20/10DF80 使用同一原字形表。
详见 static-disassembly.txt 的 10BD90、10BF20、10DF80 和 10DDB0。

每个非 ASCII Unicode 字符编码为两个原生字节，首字节 80..BF，尾字节
80..FF 排除 C4/E4/F6，代码点表跨代保存。两个原生 8x10 半格构成 16x10
字格。原 strlen、tokenizer、居中、按钮和 cursor 推进看到的字节宽度
与最终字形半格完全一致；没有把 UTF-8 直接送入原 ASCII 度量路径。
ASCII、空格、<br>、[ENTER] 和 key. 标记原样进入原解析器。

三个原字形 CALL：
10DE4D E8 3E DF FF FF → 10BD90：ECX=x，EDX=y，栈 glyph。
10DF36 E8 E5 DF FF FF → 10BF20：ECX=renderer，EDX=x，栈 y,glyph,R,G,B。
10E216 E8 65 FD FF FF → 10DF80：同上；保留原六 DWORD caller cleanup。
普通中文暂换原字体表后让上述原函数正常执行，保留 10DC50 矩形缩放和
10DF80 的临时渲染目标、glyph 纹理与目标恢复，未另写中文呈现管理器。

114680 普通按钮先逐字节构造单字符字符串。11492D/114956/1149D2
Before 从原 [EBP-A4] 全输入及 EBX 字节下标解码 Unicode 与半格，按
token 保留纯值上下文；原字符调用结束后释放。ESC. 等标签仍走原
1149F9 完整字符串链。[ENTER] 仍由原 10E720 拆出原生键帽。

文字构建与测量前接入
====================
- 主菜单标签与设置正文在原完整文字调用处换参数，不写原行位置和命中。
  设置说明保留原两个前导空格；路径不再重新取当前目录，保留原 _getcwd。
- 版本在原 sprintf 后写回原缓冲，直接使用原版本 getter 的实际参数，
  支持其最多 79 字节原值；不经过旧 MainMenuRequest.version[32]。
- 主菜单与设置页脚、鸣谢正文使用原 162300 append 和原 <br> 结构。
  当前词库鸣谢最长 token 为 68 字节，含 NUL 69，低于原 0x82 槽。
- 标题和按钮在原面板/控件参数边界提供中文，由原生函数自己计宽。
- About 124A30/124AB8、开场神话 125423 的原指令均为
  8A 01 41 84 C0：MOV AL,[ECX]; INC ECX; TEST AL,AL。
  首轮在原缓冲写中文，再执行该原指令并回原 JNE/strlen；后续居中、
  行距和渐变仍执行游戏原代码。神话原缓冲容量 0x6C，当前文字均能容纳。

上述三个内联位置通过 adapter 创建进程期稳定小代码块，块内 E8 CALL
登记到既有通用 HookHost，原指令副本和返回均只引用游戏/稳定块，不引用
业务 DLL。原位置 JMP 到该块，原 EAX/ECX/flags 由既有桥保留；没有修改
驻留 DLL。块地址及字形编码、活动 Host 堆参数和临时字形备份跨代保存。
稳定代码块在进程期保留，防止原位置或在途调用指向已卸载 DLL。

当前原生缓存的重建
==================
主菜单和 About 热应用通过原生 UI 重建，不缓存整页中文字再补画：
- 重入原平衡栈绘制片段 125BA3..125BE1。它自行执行原 Footer、面板
  参数、版本和菜单绘制；在 MenuRender 返回后，经稳定 RET 小块返回
  驻留 native_call，不进入原输入调用。没有将原坐标抄入 Mod。
- 主菜单更新原 A1C1CE0 工作缓存，再由原 D0650 保留当前选择框。
- About 使用原 10DA60 恢复背景，原绘制片段生成含中文的主菜单，
  原 10DA10 保存到 A1C2014，再重入 1247C0 原生 About 绘制。
  仅同步重绘作用域跳过 124C46 的完整 D3C80 输入入口，最后由原
  10B720 上传和呈现；不调用 drain、FlushEvents 或伪造按键。
  原来窗口的原生等待调用栈不变，不要求关闭或返回菜单。
其他已授权界面在自身原生重绘时消费新文字；模块交接不会因此等待其退出。
这项缓存重建是旧无中文背景的迁移和正常 UI 失效处理，日常文字本身已经
进入原生字体/缓存链，没有以最后叠字来掩盖原始缓存缺字。

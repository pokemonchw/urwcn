# HUD Command 原输入与旧状态迁移的静态依据

最终设计已据以下不可逆历史采用HDA8私有状态ABI，只承接完整自身状态，不接受HDA7；旧Command迁移观察器已退出实际分派与源码。当前同名inc只保留目标选择组件真实活生产者的标题读取。下文活动祖先恢复表是旧兼容研究的静态依据，不能据此声称任意HDA7活动界面都能无损热迁移。最终状态与交付见 [完整原生重建记录](20261110-language-switch-completion.md)。

本记录只使用 `/home/lulika/.local/share/Steam/steamapps/common/UnRealWorld/urw.exe` 原 PE、`build/analysis/windows-3891-native-full.asm` 和项目源码。没有运行游戏、注入、模拟操作、运行测试或编译。

## 原组件及未来输入生命周期

原 `F90D0` 的输入是 ECX 中的完整英文。`F90E4` 将其借给 ESI，`F90EB` 将显示副本格式化到本帧 `[EBP-70h]`；`F9109` 比较副本长度 26，较长时 `F910E/F9114` 将副本的第 24、25 字符改为 `..` 并写终止符。原完整输入不因此修改。

`F9118..F9149` 比较完整输入是否为 `INIT`。INIT 在 `F9161` 通过完整 `116270` 重建框，再在 `F9191/F91E7` 画 Command 标题；框内的动态命令因此成为空。普通分支 `F9198..F91E7` 用原矩形 `1DD8A0` 清空动态命令区域，再画本帧的显示副本。两条分支共用原 cookie/ESI/EBP 退出。

所以新增的普通 `F90E4` 输入边界保存完整英文；普通 INIT 提交真实空命令生命周期；同步完整 HUD 重建中的 INIT 不覆盖本次借用的已接受完整命令。只把原英文与 constructed 状态交给 HUD 序列化，不保存帧、位置、裁剪、布局、绘制贡献或像素。

## 完整生产者 census

逐字节审阅 `.text` 中 E8/E9 的相对目标与 `4F90D0` 绝对代码引用，得到 39 个直接 CALL、0 个尾 JMP、0 个绝对代码地址引用。全部直接生产者：

* `A3CA4/A3CF6/A3DBD`：子动作菜单选择后的原资源。
* `FA353`：唯一 `INIT` 生产者。
* `123360`：技能名称，完整原英文留在 `1232D0` 的 `[EBP-70h]`。
* `132784/13279F/1327AD/1327BE`：已选择物品动作的资源。
* `163979`：原 `163190` 对已接受动作 ID 的完整资源结果。
* `17D014`：主输入前的实际空命令。
* `17D124/397/4AD/50B/52B/54B/573/5AF/6AA/70A/771/78C/7B4/7DC/833/847/88C/8D9/944/962/976/ADA/AF5/B8A/BCA/BF6/C37/C73`：主动作分发。

`native_hud_command_migration.inc` 从当前真实等待帧沿原 EBP 链读取上述活动生产者的输入，最近的活动生产者优先。没有活动生产者时不会从失效栈、当前共享字符串、最后动作 ID 或默认空文本猜测旧命令。

## 活动祖先的无损恢复

`163950` 在 `[EBP-78h]` 以下保存 EBX/ESI/EDI，`163962` 将接受的 ECX 动作 ID 放在 ESI。每个直接、有 EBP 的动作子函数在更改 ESI 前按其完整原生序言保存它。实现中的 SavedInput 表逐项记录这些序言的真实对齐与保存偏移，读取原始 ID 后只调用完整、无写入、无其他 CALL 的 `163190` 资源 getter。`163190` 的控制流只有比较、跳表、MOV EAX 资源地址与 RET。

以下分支有单独证据：

* `1641A0→11DBE0` 不保存或更改 ESI；其唯一分发 ID 是 `1CAh`。
* 无 EBP 的 `4690` 只有 `163BC9/163BEE` 两个原调用者。其 PUSH ESI 在原 `163950` 帧的 `-8Ch` 处保存完整 ID；尾调消息时 POP ESI 已恢复该 ID，消息组件自身的原 ESI 保存槽仍可读取。
* 无 EBP 的 `5230/584D0/58830` 各只有一个原 `163950` 调用者，分发 ID 分别为 `196h/1A8h/1AEh`，包含其尾调消息路径。
* `1642C2/1642E5/164327` 前的原 SUB 会改变 ESI，其原始分发 ID 分别是 `2BCh/259h/384h`。`259h` 的 `1642D8→1638C0` 错误消息也按原 CALL 返回 `1642DD` 识别，不能读取已减成零的 ESI 当作原 ID。
* `1232D0` 的技能正文、选择或错误消息等待仍在 `12336F/12337D/1233B6/1233FE` 之下；原 `[EBP-70h]` 至函数退出才失效，借此取得完整原英文。
* `132060` 的 SUB `974h`、PUSH EBX、PUSH ESI 使 `[EBP-97Ch]` 保持 `132720` 已接受的选择索引。原 `132814/132800` 跳表仅接受 `0/1/2/9/t`；`0/1/2/9` 的完整资源各由原选择确定，`t` 走 `13278E` 子帧的独立资源。
* 主 `17CC80` 使用 SUB `74h` 加三个非易失寄存器保存。省略 EBP、无栈参数的原主子函数，其实际活动 CALL 返回保留在 `[main EBP-84h]`；实现只识别静态确认的这些原调用点，包含真实 `17D5F1` 空命令错误消息路径。

主分发恢复读取原指令中的资源操作数，而非复制字串或假设两个构建整体平移。`164720` 主快捷键分支的资源本体已确认，直接借其原常量，不调用这个会覆盖共享 `1EA8B8` scratch 的 getter。

`17D014` 是主输入后的真实空命令定义，后续完整 F90D0 定义按其原分支区间覆盖它。ASCII 命令在 `17E096` 退出；显示非空命令的非 ASCII `448h/43Ah` 两条路径在 `17E474` 的原跳表也直接指向 `17E096`。所以其余尚未定义命令的主分支使用该已确认空输入，是原分发的实际语义。

## F7820 标题输入的闭合恢复

原 `F7820` 先建 EBP，再对齐其局部栈。`F783F` 保存模式，`F7843` 接受 EDX 标题原指针；`F784F` 的副本在 `F8399` 后被原选择坐标覆盖，不能继续当标题字段读取。

模式 bit 0 为 1 时，`F78C4` 选择固定原标题，完全不消费传入标题；因此 `target_title` 只用于真实 bit 0 为零的原分支。其全部原调用可分为 30 个已确认 MOV EDX,imm32 操作数与 3 个动态来源：

* `F880D`：原父 `[EBP-30h]`，对应 `F8803` 原读取。
* `F8B56`：原父 `[EBP-4Ch]`，对应 `F8B4C` 原读取。
* `F8BCA`：无 EBP 的 `F8BC0` 仅 PUSH ESI，再把接受的 ECX 转为 EDX。原 wrapper 返回在 F7820 `[EBP+Ch]`，其两个调用者 `59CC/166286` 各有明确原 MOV ECX,imm32。

PE 相对 CALL census 还确认了线性反汇编在前一个跳表后漏掉的 `5238→F7820`，其标题操作数 `5232` 也已收录。这里的表只有原英文源身份与真实调用约定，没有布局值。

## 升级前已经丢失的历史输入：仍需区分的边界

旧 `hud_native.inc::hud_command` 对动态描述不调用翻译或绑定，仅对字面 Command 标题提供源。`native_component_binding.cpp` 的 `10E5A0` 分支只有 `explicit_source` 才建立中性文本组件。因此旧动态描述连本地截断副本都没有进入旧组件模型，不能凭不存在的组件恢复。

`17CC80` 开始至 `17D014` 的这一轮代码中没有 F90D0 调用；先前一轮主动作可已经返回 `180D5B`，其完整输入局部已经失效。`180D5B` 到下一次 `180D56→17CC80` 的主循环没有 FA2A0/FA353/F90D0，故不能推断这些业务、消息等待之前必定 INIT 或 clear。

原持久 `A2C6AA4` 的写入 census 只有 `163A02`、`3153D` 和初始化 `17E5F1`。`163950` 原分支明确不记录 `21h/1A4h/1A7h..1AAh/1C3h..1C7h/1CAh..1CBh`；直接主命令（例如 e/h 与信息页面）也不在此存储最后显示原输入。它的语义是可重复动作，不能解释成“最后显示命令”。共享 `1EA8B8` 也会被其他描述 getter 覆盖。

已知未构造的实际 INIT 空输入、当前活动生产者中仍保留的完整输入、以及升级前已返回且未记录的历史输入，三者不可混同。当前迁移函数不会把第三类填成第一类。本次新增完整 F90D0 输入和普通 INIT 生命周期会消除之后的历史缺失；不能把这一未来修复描述成已恢复过去未记录的完整命令。

对第三类旧状态，完整 HUD 构造的真实前置是原生 `F90E4` 再次提供完整输入，或原生 INIT / `17D014` 实际提供空生命周期。此前直接把默认构造的 `std::string` 空值交给 F90D0 仍会有损，不能消费这个未经构造的值。不能提前执行下次 `17D014` 来伪造此刻的空命令，也不能为了得到输入重跑、跳过或推动游戏业务。无损交接只能同步到真实原生命令构造事件；若要求上述已丢失历史的旧等待在此刻立即等价重建，该旧状态本身不具备无损即时迁移所需的信息。

公共背景构建与新 scene owner 边界：全量直接调用调查
日期：2026-10-19（Asia/Shanghai）
对象：不真实的世界 / UnReal World 3.89 / Steam Build 25939378 Windows x86。
原 EXE SHA256：e0b15bbbe16ffcd95d4ab61f08fe95dea4b95ebe1b3de428dae1d9477a9710d9。
全部地址为 RVA；附属 objdump 指令地址为首选基址 0x400000 下 VA。

方法
====
对安装目录原 EXE 全 .text 做离线 objdump -d -Mintel，枚举目标 1127C0
的全部直接 CALL；随后读取调用前参数准备、1127C0/1124A0 完整指令、
10C790 的背景资源初始化，以及已安装三个 PNG 文件的容器元数据。
没有启动游戏、执行函数、注入、模拟操作、运行交付产物、编译或测试；
没有创建测试或断言。PNG 调查只读 IHDR/chunk 名称，没有游戏像素跟踪。

原始证据：
- 20261019-global-language-background-calls-disassembly.txt：19 个调用
  的前 24 条和后 5 条指令；背景加载和实际绘制函数；PNG 元数据与哈希。
- 20261019-global-language-root-lifecycle-disassembly.txt：清屏、一级
  背景保存恢复、二级背景保存恢复的全量直接 CALL/JMP 上下文。
- creation-complete-background-disassembly.txt：完整 1127C0。
- static-disassembly.txt:493-615、1041 起：二级/一级缓存完整函数。

结论
====
1127C0 的全量直接 CALL 为 19 个，全部明确传入目标宽 800、高 600；
没有任何一个直接调用传入局部矩形尺寸。本函数不读取调用者的 x/y，
其目标由 1124A0 固定为主面原点。13 个调用从固定背景文件加载；另
6 个调用使用 10C790 预先加载的三个背景 surface。此直接调用集合中
没有局部背景反例。

因此，在用户最新授权的“Hook 修改原生 UI”实现中，可以把已成功
完成的这类完整背景构建定义为新 scene owner 的创建/替换边界；后续
公共组件构造绑定这个明确的新 root，而不必猜测最近面板或矩形归属。
这是对原生生命周期的新增协议定义，不是宣称原程序已经有 scene 树。
它只解决这类 root 构建和归属的依据，不自动解决组件源、更新、销毁、
布局及全部缓存的协议，也不授权保存文字/位置贡献序列来重放。

本结论只穷尽已解析 .text 的直接 CALL。它不声称未解析间接调用绝对
不存在，也不声称所有游戏画面都通过这个函数开始；10B9F0 和其它
独立构建族仍有自己的原生生命周期。

一、1127C0 的原生契约和全屏输出
=============================
ECX = filename（当 EDX=0 时使用）。
EDX = 已加载 SDL_Surface*；非零时不重新加载。
栈第 2、第 3 个 DWORD，即 [EBP+10h]/[EBP+14h]，为目标宽/高。
栈前两个 DWORD 在完整函数内未读取。19 个 caller 都为这两槽预留
8 字节；不要把未初始化的预留槽解释成 x/y 或 UI 布局字段。

1127D5/1127D7 分别保留原 EDX/ECX；1127DA 分加载分支。
112854..112897 按 filename 有无 '/' 加 truegfx/ 前缀并 IMG_Load。
1128A2..1128CE 是原生加载失败返回，未进入绘制；新 root 协议应在
实际完整背景绘制完成后提交，不应把失败返回记成成功覆盖了旧 root。

成功路径在 11294E 调 1124A0，随后仅在自行加载资源时于 11295B
SDL_FreeSurface；外部传入 surface 仍由原游戏 owner 持有。

1124A0 的缩放分支：112548 将传入目标宽写到目标 rect.w；112558
和 112561 分别把目标 rect.x/y 写为 0；112568 把目标高写到 rect.h；
11256B 对原主面 61BBB10 执行 SDL_UpperBlitScaled。原图尺寸相同
时走 112584..112591 的原生普通 blit。所有 19 调用的目标为完整
800x600 原生主面域，而非 Mod 复制的页面位置或行槽。

1127C0 可用全局前置内联点为 1127C9 的单条
    A1 0C 20 5E 00    MOV EAX,[cookie]
此时原 ECX/EDX 和 EBP 栈参数仍完整；绝对操作数须按实际 image_base
重定位为 image_base+1E200C。实际绘制提交点可用本作用域内
11294E -> 1124A0 的 After；该调用不经过上述加载失败返回。
这些只说明可用原始指令，不表示已经实现或编译了新 Hook。

额外的预留 DWORD；新包装器应自行平衡自己实际传入的四槽，不能据

三、背景文件透明度的静态范围
===========================
已安装 bg-backstory.png、bg-deathscene.png、bg-urwstart.png 的 PNG
IHDR 均为 bit_depth=8、color_type=2，三个文件均没有 tRNS chunk。
这三个实际文件没有 PNG alpha 通道或透明色；其哈希记录在原始证据。
其余四个源为 JPG。此结论针对列明哈希的已安装原资源，不擅自推导
用户之后替换的图片或未知 surface 别名具有相同内容。

四、10B9F0 是完整软件根清理，但不等于业务页面退出
=================================================
本函数无 UI 位置或尺寸参数。在 10BA00 读取原矩形 1DDAB0，
10BA17 对主面 61BBB10 调 SDL_FillRect，色值0；矩形为原生
{0,0,800,600}。因此它可定义“当前软件 root 内容清除”的统一边界。
其后仍按原开关执行上传、overlay、呈现；不应把它当成单纯的无副
作用 memset 并额外重调完整函数。

全 .text 有17个直接CALL和10D9FC一条尾JMP。直接CALL RVA：
133BC,3A391,60B7D,61138,B0E61,D7A6C,DE9DE,E6D47,E6E6B,E7311,
E74E4,F619A,F61EE,F6262,1038CB,1257BB,15DD9C。

有些调用是页面入口，有些为结束清理，还有 F6180 中的 BMP 导出
流程：F619A清主面 -> E0760构建技能背景 -> F61C0复制到导出工作面
A1C1C98 -> SaveBMP -> F61EE再次清面 -> 后续绘制/导出 -> F6262清面。
所以 root 清理是原生绘制内容的生命周期事件；不能把它解释成取消
输入、关闭游戏窗口或永久释放所有由原生缓存仍持有的父 scene。

五、保存恢复定义 owner 引用，不保证是函数形式的统一入口
===================================================
一级背景 A1C2014：10DA10 在10DA3C保存主面；10DA60 在10DA71恢复；
10DAD0 在10DAF1恢复并管理原呈现/overlay状态。保存到同一原生槽时，
新协议可以让该原生缓存 owner 持有当前 root 的引用；恢复时切回该
引用，并由其原生组件重建流程更新同一缓存。不得保存文字贡献列表。

但全 EXE 的 10DA10 直接CALL只有17D84C这一处。主菜单打开子窗口
的125C2B/125C77/125DC7/125DFC/125E34/125E69/125E9E等均直接
内联 SDL_UpperBlit 到 A1C2014。因此只Hook10DA10不能覆盖父root
保存；必须按实际原生cache写入契约覆盖已确认内联保存入口。
当前14个10DA60直接CALL和6个10DAD0直接CALL同样不是这些内联
保存存在与否的证明，不能配对推测未见过的保存。

二级背景 A1BBD24：10D340 在10D375保存，且仅在61BBAFC==0时保存，
10D37E置标志1；10D3A0在10D3B1恢复，10D405清标志；10D420在
10D441恢复并保留其原overlay/呈现语义。新协议必须保留这些原生
条件和实际槽身份，不能把它们统一改成任意压栈/弹栈规则。
四个10D340、四个10D3A0、七个10D420直接CALL见附属全量调用窗口。

命名缓存 A1C1CC4[4]：10C540保存/同名替换，10C690恢复，10C4C0
清名字和释放surface。owner引用的保存、替换、释放应依附这些原生
动作。既有 A1C1CA0 仍是原 rect 指针，不能把它伪装成 Mod scene 指针。

实现边界
========
这次调查给出了明确的公共新root创建事件：成功的1127C0整屏背景构建，
以及10B9F0完整软件面清理。可以按实际原生缓存把root所有权跨保存/
恢复持有，后续公共原生组件构造绑定当前root；没有必要靠页面ID或
最近panel矩形猜归属。

接下来的实现仍须将原生组件真正改为有源、布局、paint和retire的类型
协议，并在它们原来的生命周期内消费语言；不能把所有10E5A0的输入
保存成命令列表，换语言时另行遍历排版或绘制。不能因为root边界已确认
就宣称任意已打开的旧版本画面已具备新对象，或未知构建路径已覆盖。

本轮只新增上述静态调查文件，没有修改运行源码，没有编译、发布或
运行时交接。

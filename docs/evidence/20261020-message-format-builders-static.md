## 分类及限制

`settlement-formats-final-exclusions.tsv` 将旧同缓冲区候选中剩余 46 处逐项分为：21 处纯文件日志、6 处文件路径、3 处业务数据、12 处其他原生界面、4 处由菜单代理接入的共用消息片段。附近存在消息调用不等于同一缓冲区写入会显示。巨型调度器剩余分支另见主代理的 `settlement-dispatch-final-classification.tsv`。

格式配方数量只是构建入口数量，不证明参数来源全部闭合。`4367E0 / 46D3E0` 新生成复合名称的构建、两处后续复制及旧存档名称语法恢复见下节；肉类 `cut` 的实际生成来源和未终止复制身份见下文，不能以已注册入口数量表示整个消息区已完成。任务标题的旧 `type35` 源仍由主代理独立追踪。

## 材料与目标名称构建

`436973 / 46D4FE` 调用 `467A30`，模式分别为当前材料记录 `+8` 和该字节的本地副本 `EBP-1A9`。`43697A / 46D503` 将真实返回文字复制到 `EBP-140`。`4369B1 / 46D531` 在原生首次选中材料的复制循环首迭代绑定首材料；`4369FD / 46D579` 仅在原生材料比较已经不相等的分支将实际 `Mixed` 文字绑定为混合材料。

`436A68 / 46D5E8` 在原生 `rep movs` 入口保存实际名称后缀复制的源；此时原生格式前缀已经是 `%s `，EDI 正是后缀目标。它们只覆盖默认命名分支：更早的 `436909 / 46D4A4` 会先复制需求记录 `+9` 的 `[name:...]` 模板，非空时不会进入默认分支。`437059` 的原生饮料分支又可覆盖为 `%s beverage`。

因此 `437140 / 46D63B` 读取完整实际格式，以 `crafted-name-format` 精确源词条保存：139 个已安装配方的原生小写后缀、7 种 glossary `[name:...]` 格式、饮料格式和 `437400` 写入的 6 种原生烹饪格式，去重后共 150 条。这包含 `dried %s soup`、`smoked %s soup` 等参数前仍有文字的格式，不再无条件假定 `%s` 位于前三字节。所有 native 格式、参数和目的缓冲保持英文。

`43710F` 为原生直接采用配方名称的复制分支，`437177` 为原生采用 `451770` 完整名称的分支。它们与 `437140` 一起绑定真实 `0067D521` 物品名字字段。`46D63B` 绑定返回缓冲 `018FE3D8`。`4416A0` 的后续传播边界 `4425DE` 已绑定返回值到 `EBP-A58`，非空分支 `442610` 的首次 `ECX=0` 迭代绑定新物品记录 `+9`（`EBP-EFF`）。两段原生复制均无中间调用。

`4C0AC0` 保存完整 `0xAC` 字节描述记录；`4C0110 / 4C0190` 读取同样的原始记录，不持有原构建栈。`windows_message_crafted_items.inc` 因而在实际描述记录的基础名字边界恢复中性源语法，而非依赖一次构建时的中文快照。`451A97` 的 `args[2]-9` 是原生已经选择并复制到本地的描述记录，包含 `ECX=-1` 与容器内容分支后的实际选择。

该恢复只识别精确库存原子以及已证单 `%s` 产生式；递归参数每次都比完整源短。库存源含 `material.field / material.word / material.cut-native`，配方、物品、植物原子；木材替换保存实际英文 `%s shovel` 等模板及对应树种，供最终显示和原生文字截取沿同一源节点处理。没有以未知字符串作为专名或原文回退。命名选择字节 `+0x93=1` 是保留生成名字的分支，原生也允许调试命令设置它，因此它不单独证明某个名字属于一种复合格式；完整源仍需匹配实际库存或语法。未属于该语法的输入沿现有 `Status::unavailable` 返回，没有自行补造业务行为。

皮类来源另由 `51CEC0 / 51E9D0 / 51E140 / 51E7B0` 确认：物种来自 creature record `+8`，原生最多保留 25 字节，并存入描述记录 `+0x31`；它不是 creature 的 `+0x30` 专名。`%s-skin`、clean/de-haired 变体、`%s fur` 与 `%s leather` 使用专门的物种词源和格式。两个超出 25 字节的已知原文大小写变体保留原生截断拼写作为键。对应 ID 为 `19A / 19C / 19D / 19F`。`57C80C -> 4C0D40` 只修改质量位，不写名称。`436BD3 -> 4BC880` 目前确认为查询调用，未添加所谓材料复制 hook。

材料生产者 `467A30` 的完整 C 位于 `settlement-npc-introduction-gates-ghidra.c`。它可选 `451650` 材料、完整物品名、原生截取或模式 `98/99/100` 的其他分支，不能当作只有六个常量的普通 material 域。该生产者和 `451650` 由主代理负责。

## 原生消息工作缓冲静态复核

已复核主代理在 `windows_messages.inc / windows_message_display.inc` 的三段动态文字工作存储：source、word、history 每段容量为本次编码结果含终止符的实际字节数。原生循环只消费 source，word 与 history 只加入已经消费的字符；中文词元按完整两字节编码移动，颜色标记与换行跳转仍走原生分支。没有通过截断中文规避容量问题。

十三处 source/word/history 操作数替换覆盖当前 `F6510` 文字循环；`F6DE4 / F6E35` 继续消费原英文以保持日志/声效分支。绘制调用参数顺序由实际 push 证明：文本为 `arguments[0]`，`arguments[2]` 是原 outline。当前代码已按此修正。分页等待仍持有同一 EBP 与原生 UI 生命周期，正文范围按本次 EBP 查找。详细容量与寄存器证据见 `20261020-message-text-capacity.md`。

格式和专用拼接收集器没有建立新 UI、延迟像素重放或整页布局。它们保留中性源图；最终中文投影和编码发生在主代理负责的原生显示借入边界。
## 肉块与原生材料尾字节

`434548 -> sprintf("%s cut")` 是实际肉块名字生成点；`434500` 同时把同一个原生物种源复制到记录 `+0x31`，设置类别 7、ID `0x1F4`。九个调用者已逐汇编确认：八处直接 creature record `+8`；`51CC66` 经 `4AD4F0(flags=1)` 提前返回 human/class，绕过已知身份、专名及幼年修饰。证据为 `settlement-meat-name-builder-ghidra.c`。因此普通肉块的基础名字可恢复为物种源加“肉块”，未把任何玩家名称解释为物种。

`451650` 对类别 7 / ID `0x1F4` 直接返回该 `+0x31`，不会进入 flora 分支，所以这些普通肉块不会以 `tuntematon` 进入 `467BDB`。`433E10` 在首次加入食材时把完整 `0xAC` 描述记录复制到 `0067D518`，其中包含 `+0x31`；后续只对谷物 `0x1B4` 和蘑菇 `0x201` 的材料差异写入 mixed/mushrooms。不能把这一结论推广为原生 `cut` 分支永远不可达：该实际分支仍保留。

`467BDB` 的精确前置条件为类别 7、完整名字含 `" cut"`、`467BB2 -> 4D4310(2130878,59686C)` 返回 1。`59686C` 是 `tuntematon`，`4D4310` 在局部小写副本上做完整匹配（`4D4384..4D43AE`；允许的通配符属于原生匹配规则，当前材料库存没有它们）。这不是命名模式 14 的条件。

原生 `467A4B` push 100、`467A58` push 0、`467A5C` push 2130878、`467A61 -> memset` 清空整个材料缓冲。`467AE7..467AFF` 复制 `451650` 结果。其后两条替换分支只写完整物品名，不再写回 unknown；达到上述 unknown 条件时，长度 10 后的原生清零尾不应被猜测为任意字符串。`451770` 的实际类别 7 路径不会重入 `467A30`：类别 12 尸体、8 木材、6 绳索的其他生产者均未进入；实际质量、字符串比较、小写与复数函数的完整 C 均无该调用，且本次 count=1/flags=4。因而这段清零尾由原生调用链保持。

本次 `467AA8 -> 451770` 的 count=1、flags=4 会跳过 quality/stale 整段；独立腐败分支仅类别 5 选择 Rotten，类别 7 选择 Spoiled，最后 `452586` 拼接再由 `4D4020` 将结果小写。因此 cut 路径实际前缀只有空前缀或 `spoiled `，不是 stale/Rotten。当前库存把真正选中的语义前缀保存为 `material.cut`；持久化名字使用单独的 `material.cut-native` 精确源键。对于短于 10 字节的已证前缀，键为前缀加 `tuntematon` 的未覆盖后缀；更长前缀的键为前缀本身。该域不用于任意未知字符串的后缀匹配。格式参数与源图继续记录原生实际字节，最终中文按前缀语义生成。生成入口为主代理的 `generate-settlement-material-values.ps1`；本代理的 `generate-settlement-crafted-grammar.ps1` 只消费该固定域。

## 格式参数与内联指令审查

37 条原先标为 item 的格式配方已按真实生产者分开：32 条使用本次 descriptor `+9`（CRT `_strlwr` 返回同一地址），由 `message_crafted_item_source` 读取该真实描述记录；`435B90 / 52DC85 / 52DD3F / 52DDFE / 52DE72` 是 `4D4020` 返回的临时字符串，消费其绑定源。格式收集帧记录 `source_status`，before/after 成对，失败状态直接传出且不绑定空源；该字段包含在热更状态序列化中。全部数字与格式变参仍保留原顺序和类型。

66 处内联边界的实际指令清单保存在 `settlement-format-builders-inline-boundaries.tsv`，包含展开的 7 处治疗复制、2 处 Mixed 选择及绝对地址操作数。静态审查查阅完整反汇编的直接 jump/call/loop 目标，没有发现外来直接边进入当前覆盖区间内部；复制循环回边均落在挂钩起点。

- `5079BB` 原位置含 `ADD ESP,0C`，已改 `5079C0` 单条 7 字节 MOV；只有原生 ECX=0 首迭代建立副本源。
- `565B7C` 原 expected 错漏实际 `ADD ESP,4` 并会截断该指令，已改 `565B84` 的完整 `MOV CL,[EAX]; LEA EAX,[EAX+1]`。此时 EDX 已由原生减去源地址，仅 `EAX+EDX==EBP-70` 的首迭代建立副本源；native 的 ADD ESP 已在挂钩之前完成。
- `507851` 是原生相对 JMP，处理器明确设置 `resume_rva=0x1076C0`，不从跳板重放相对位移。
- 其余覆盖指令为完整 MOV/LEA/MOVQ/IMUL/INC/SUB/SHR；没有 ESP 调整或相对控制转移。两条指令的覆盖区间保留原生顺序与 EFLAGS 写入；消息源处理器不改变 NativeFrame 寄存器，原生重放继续产生这些结果。绝对读地址根据 image base 填入 expected。

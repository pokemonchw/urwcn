# 百科父缓存及动态菜单语言重建（3.89.1）

只读依据：安装目录原 `urw.exe`，SHA-256 `c6ed73642c1b1cb1f86b818c7586224398c2f0554f6114ced31bc40ff071806d`；`build/analysis/windows-3891-native-full.asm`；对函数边界另做定址反汇编。以下地址均为 RVA，非 VA。没有运行游戏、产物、测试或测试脚本，没有编写断言。

实现：`modules/adapter/native_parent_cache_language.inc`。接口为 `append_hooks`、`dispatch`、`menu`，以及共同缓存整合的 `second_parent`、`restore_hud_named`、`game_parent`、`course_reward`、`restoring_first_hud`；包括位置须在 `native_full_language.inc` 之后。分派在 `native_full_language::dispatch` 之后、`native_language_redraw::dispatch` 之前，菜单回调在普通完整 `CFFB0` 重绘之前。新增 Hook IDs 为 `5152..515F`、`5180..519E`、`51C0..51D5`。

## 原生缓存所有权

`DF7B0` 包装百科：`DF86B -> 10C540("infobrowser",0)` 原生保存完整父界面；`DF8AA -> 3E680` 运行百科；`DF8C4 -> 10B1F0` 从真实栈上的 80h 字节参数恢复原可见性。之后分别在 `DF8ED`（淡入分支）和 `DF935`（普通分支）调用同一原生 `10C690` 恢复父缓存，随后原生 `10C4C0` 释放。

`10C690` 不只是复制缓存：完整恢复路径 `10C727 -> 10AF90`、`10C74C -> 10B3C0`、`10C760 -> SDL_RenderPresent` 会立即显示，所以只刷新百科当前页不能修复关闭时的旧语言恢复。

两处恢复 CALL 的 Before 保有真实 `DF7B0` 帧：`[EBP+4]` 是外部调用者返回地址，`[EBP]` 是真实父窗口 EBP，`EBP+8` 是调用百科时父窗口的真实正文 ESP，`[EBP-490h]` 是父窗口原 EDI。EBX 按原调用约定保留。没有保存原生帧或整页字段快照。

构造期间激活该真实父 cache 的 `saved_background(slot)`，HUD 消息等原组件因此以实际父 Root 查找语义 owner；同名 save 后恢复原当前 Root 身份，后续原 native restore 再按其缓存所有权激活新父 Root。百科已构造的 Root 不能冒充父窗口 Root。

在原 `flip=1` 不显示分支先调用同一 `10C690` 恢复实际父像素底，保留原游戏场景和非文字图像；随后完整原生语义构造替换本族 UI，最后同名保存。命令/物品/伤势窗口另沿原 `10DA60` 恢复它们真实 first 背景，再构造 HUD、原 `10DA10` 更新 first，之后构造前景；定位菜单用原 `1AAD40` 矩形恢复底层再更新。否则把尚有前景窗口的像素存入 first 会破坏之后的正常关闭。所有复制均为游戏自己的已有 cache 操作，不读取或保存像素到 Mod。

定位菜单的原局部恢复是例外：`10C77A -> 10B770(...,1)` 不检查 flip，会立即上传/显示。只在本次同步 `1AAD40` 底层恢复期间跳过这个已完成复制之后的上传 CALL，原矩形与原像素复制保持；完整父构造后由外层真实 D1120 或原完整 named restore 统一显示。普通运行的该 CALL 不改变。

先按真实 ECX 名称与原四个 100 字节命名槽（`A1C1AC0`）求槽号；使用共同 `native_ui_scene::cache_needs_language(slot)` 比较该真实缓存的语言 revision。需要更新时调用对应完整原生父构造，再调用原 `10C540` 保存同名、同全屏参数；继续原 `10C690/10C4C0` 的复制、显示、释放生命周期。原生 save 自动提交 revision，各缓存独立更新，不依赖一次全局 pending 消费。
